## JSP 제공 후 추가 검증

제공된 `WEB-INF/login_mfa.jsp` 소스와 직접 연결된 패딩/데몬 코드를 분석했다.
분석 결과와 적용 위치는 [JSP 분석 문서](JSP_분석현황.md)에 있다.

- 신규 `src/test/java/com/scbk/mfa/service/MfaSocketFlowTest.java`: **1건 통과**, 실패/오류 0.
- 명령: `mvn -B -ntp -Dtest=MfaSocketFlowTest test`.
- 실제 MfaTcpServer + MfaService와 상태를 보존하는 메모리 저장소로 소켓 5회 수행: A→B200, 잘못된 시퀀스→D401, 잘못된 OTP→D401, 정상→D200, 재사용→D401.
- B 응답에서 시퀀스/OTP를 각각 추출하고 그 시퀀스로 C를 생성한다. JSP의 flush/shutdownOutput/readLine EOF 방식 및 ASCII 응답을 확인한다.
- `bin/verify.sh io` 대상에 이 테스트를 포함했다. 최초 60건과 신규 1건의 별도 실행 결과이며 **전체 61건을 한 번에 재실행한 결과는 아니다.**

문서에서 추출한 MfaTcpClient는 실제 Spring annotation JAR로 컴파일하고, 요청 EOF를 받아야 응답하는 loopback 모의 서버에서 **8개 검증을 통과**했다.
A/C의 106바이트, SMSADMIN 채널·행번·시퀀스·OTP 위치, A→B→C→D, D401, 잘못된 응답 유형, B500/D500/E400 및 잘린 응답 거부를 확인했다.
이 검증은 문서 클라이언트의 기존 데몬 EOF 방식 대응을 확인한 것이며 실제 기존 데몬/Oracle/SMS에 연결하지 않았다.
임시 검증 파일은 `/tmp/mfa-jsp-eof-client-verify/`에 있으며 배포 소스가 아니다.
문서의 신규 Java 4개 클래스와 실제 SMS ApiResponse를 함께 javac 컴파일하여 변경된 verify 인자와 Controller 연결도 확인했다.
