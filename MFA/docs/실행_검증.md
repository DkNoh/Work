# NEW_MFA 실행·검증

이 디렉터리의 Maven 빌드 대상은 독립 MFA 데몬이다. SMS는 별도 프로젝트이며 여기서 기동하지 않는다.

## 준비

JDK 21, Maven, Linux Bash, flock이 필요하다. 의존성과 플러그인은 폐쇄망 Maven 저장소에 반입한다.
실제 DB 인증정보는 외부 환경변수 `MFA_DB_URL`, `MFA_DB_USERNAME`, `MFA_DB_PASSWORD`로 주입한다.
예제에는 인증정보가 없고 query.*는 실제 테스트 DB DDL과 대조해야 한다.

```bash
cd /home/dk/Work/NEW_MFA
cp conf/mfa-local.properties.example conf/mfa-local.properties
cp conf/mfa-dev.properties.example conf/mfa-dev.properties
chmod 600 conf/mfa-local.properties conf/mfa-dev.properties
```

예제 local은 127.0.0.1:9200, dev는 127.0.0.1:9201이다. 실제 대상 주소/포트를 확인한 뒤 설정한다.
로컬 Oracle은 기존 oracleup만 사용하며 볼륨을 삭제·교체하지 않는다. 이 쉘은 Oracle을 자동 기동하지 않는다.

## JUnit

```bash
./bin/verify.sh unit    # 설정·전문·인증 서비스
./bin/verify.sh io      # Hikari/JDBC·TCP·JSP 방식 발급→검증 흐름
./bin/verify.sh shell   # 실행·HealthCheck·Sonar 쉘 계약
./bin/verify.sh all     # 이 데몬의 전체 관련 테스트
```

테스트는 H2 메모리 DB, fake repository, loopback TCP 및 fixture 프로세스를 사용한다.
운영 DB·LDAP·실제 문자 발송은 하지 않는다. source 파일은 `src/test/java/com/scbk/mfa`에 있다.
JUnit 결과는 `target/surefire-reports`, JaCoCo는 `target/site/jacoco/index.html` 및 `jacoco.xml`이다.
부분 테스트 후 커버리지는 그 실행 범위만 의미하므로 분석 전 전체 관련 테스트로 보고서를 생성한다.

JSP의 소켓 흐름만 확인하려면 `mvn -B -ntp -Dtest=MfaSocketFlowTest test`를 실행한다.
실제 서비스와 loopback TCP에서 A→B200, 잘못된 시퀀스/OTP→D401, 정상 C→D200, 재사용→D401을 검증한다.
JSP의 송신 EOF와 응답 readLine 방식을 재현하지만 JSP/WAS 실행 자체는 아니며 DB/SMS는 메모리 저장소로 대체한다.

## 빌드·기동·상태·종료

```bash
mvn -B -ntp package
./bin/mfa.sh local start
./bin/mfa.sh local status
./bin/healthcheck.sh local
./bin/mfa.sh local stop

./bin/mfa.sh dev start
./bin/healthcheck.sh dev
./bin/mfa.sh dev stop
```

MFA_CONFIG/MFA_JAR/MFA_JAVA/MFA_RUN_DIR/MFA_LOG_DIR로 경로를 지정할 수 있다.
각 환경의 PID·로그를 분리하고 PID/start time/JVM marker를 확인한 프로세스만 종료한다.
기동 확인/종료 기본 대기시간은 각각 30초다. MFA_START_WAIT_SECONDS/MFA_STOP_WAIT_SECONDS로 조정한다.
실제 데몬은 Hikari 초기화에 DB가 필요하다. DB 없이 동작하는 것은 JUnit의 fixture다.

## HealthCheck

신규 데몬에 Z+공백의 106바이트를 보내 예상 E/400 응답을 검사한다. 발급/검증·DB·문자 큐는 호출하지 않는다.
소켓만 연결하는 검사보다 요청 처리 상태를 확인하지만 DB 상태와 문자 수신까지 보장하지 않는다.
원본 MFA에 그대로 사용하는 도구가 아니다.

| 종료코드 | 의미 |
| --- | --- |
| 0 | 예상 TCP 응답 정상 |
| 2 | 연결·응답·timeout 실패 |
| 3 | 응답 형식/코드 불일치 |
| 64 | 인자/설정 오류 |

## 정적 분석

`./bin/static-check.sh`는 컴파일/JDK 내부·폐기 API/쉘 문법 검사를 수행한다.
Sonar 관련 설정과 미실행 범위는 [Sonar 분석 안내](정적분석_Sonar.md)에 구분한다.
