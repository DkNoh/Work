## 현재 출발점과 보존할 동작

005의 시작점은 `ScActionButton`, `ScTextField`, `ScAppShell`이며 현재 공개 UI는 20개다. 기존 부품의 이름을 바꾸거나 같은 동작의 래퍼를 하나 더 만들지 않는다. 신규 공통 부품은 파일/import `Sc...`, template `sc-...`, CSS `.sc-*`와 SFC `<template>` → `<script setup lang="ts">` → `<style>` 순서를 따른다.

[ExamplesPage.vue](../../frontend/apps/reference-app/src/features/examples/ExamplesPage.vue)는 등록·수정별 VeeValidate `useForm`/`defineField`, 기능 [schema.ts](../../frontend/apps/reference-app/src/features/examples/schema.ts)의 Zod `safeParse`, [api.ts](../../frontend/apps/reference-app/src/features/examples/api.ts)의 runtime client를 사용한다. 제목은 trim 후 필수·200자 이하다. 이는 공통 입력의 고정 규칙이 아니라 중립 예제의 업무 규칙이다.

페이지는 Router query의 `page/edit`, 서버 목록은 Vue Query, 입력은 두 폼이 소유한다. 재조회가 같은 선택의 dirty 입력을 덮지 않으며 409 실패에도 `resetForm`을 호출하지 않는다. 성공·명시적인 편집 취소·최신 내용 불러오기에서만 의도에 맞게 초기화한다. 기존 미저장 이동 확인과 beforeunload를 새 대화상자/배치로 바꿀 때도 결과를 보존한다. 현재 로그인은 별도 로컬 ref 폼이며 로그인 화면까지 VeeValidate로 구성된 것으로 기록하지 않는다.

[Starter StartPage](../../frontend/apps/starter-app/src/StartPage.vue)는 로컬 프로젝트 제목과 공개 `/api/health` 조회만 갖는다. Reference 업무 코드를 import하지 않는다. 새 모듈의 최소 합성 소비 예제를 제공하되 Starter의 업무 DB/schema가 필수로 생기지 않도록 한다.

토큰 원본은 [tokens.ts](../../frontend/packages/ui/src/tokens.ts)다. 본문 14px·제목 24px, 입력/버튼 6px·카드 8px·일반 대화상자 12px, sidebar 248px·content 최대 1280px, breakpoint 768/1200/1600/1920px와 reduced motion을 재사용한다. 공통 테마·CSS 생성 값과 카탈로그가 다른 숫자를 관리하지 않는다.

최종 이름·props/defaults·event payload·slot·attrs 전달 DOM은 구현한 공개 타입과 [UI 공개 계약](UI-공개계약.md)·세 하위 계약 문서에서 확인한다. 위 표는 공통 책임을 요약한다. 기존 버튼 default type/submit/reset·busy guard, 입력의 문자열 model·Field role 제외·고유 ID·전체 오류 표시를 유지한다. 임의 `$attrs`·Vuetify props/slot·렌더 callback을 통째로 공개하지 않는다.

모든 업무 HTTP는 `@sc/runtime` client를 사용하고 `/api`·쿠키 세션·CSRF·30초 timeout·필드 오류·이전 세션 응답 폐기를 유지한다. 입력은 VeeValidate 문맥 또는 해당 로컬 폼 하나에 두며 Zod 4 `safeParse`를 직접 연결한다. 호환성이 확인되지 않은 Zod adapter를 추가하지 않는다. [VeeValidate useForm](https://vee-validate.logaretm.com/v4/api/use-form/), [Zod 기본 사용법](https://zod.dev/basics)

현재 [중립 API](../api.md)의 `/api/examples`는 0 기준 page/size와 ID 내림차순이며 검색/선택 정렬 인자는 없다. 기존 API가 서버 검색/정렬까지 지원한다고 가정하지 않는다. 005의 표는 제어되는 sort/page/filter event와 MSW 서버 상태를 재현하고 실제 중립 API의 페이지 흐름을 연결한다. 실제 중립 검색/정렬을 확장할 때는 Reference 앱의 단순 조회로 구현하고 허용 필드·기본 순서·total/count·기존 요청 호환을 문서/명세/타입/서버 테스트와 함께 갱신한다. 009의 MyBatis 복잡 권한/count·성능 검증은 별도로 완료해야 한다.

## 표·가상화·다국어의 확인 기준

TanStack Table은 행 모델/정렬/페이지/선택, Virtual은 표시할 렌더 범위, Vue Query는 서버 자료를 담당한다. 화면은 SFC template와 slot으로 작성한다. 공식 `/latest` Table 문서는 현재 v9 API를 설명하므로 v8의 `useVueTable`와 v9의 `useTable/tableFeatures` 예제를 혼용하지 않고 실제 선택 버전으로 검증한다. 예제의 `h()`·JSX를 공통 셀 렌더 계약으로 반입하지 않는다. [TanStack Vue Table](https://tanstack.com/table/latest/docs/framework/vue/quick-start), [Vue Virtual](https://tanstack.com/virtual/latest/docs/framework/vue)

- 행 선택은 배열 index 대신 업무의 안정적 ID를 사용한다. 정렬/필터/페이지 후 선택된 행이 다른 행으로 바뀌지 않아야 한다. 페이지 밖 선택·전체 선택의 범위와 초기화는 공개 계약에서 명시한다.
- 서버 페이지를 받은 뒤 현재 page만 client 정렬하고 전체 서버 정렬처럼 표시하지 않는다. sorting/filtering/pagination의 client/server 모드를 명시한다.
- native table의 caption/header/scope·정렬 버튼·aria-sort·행 행동 이름을 확인한다. 단순 표를 `role="grid"`로 바꾸고 화살표 키 계약을 생략하지 않는다. [WAI-ARIA Table pattern](https://www.w3.org/WAI/ARIA/apg/patterns/table/)
- 가상화는 10,000행을 실제 스크롤하며 렌더된 행 개수/overscan 상한을 수치로 기록한다. 첫/중간/끝의 ID와 내용을 비교하고 긴/가변 높이·resize·정렬 후 측정을 확인한다.
- virtual DOM 밖으로 focus가 사라지거나 잘못된 row index/count를 읽지 않도록 설계한다. 필요한 ARIA 전체 개수/행 위치와 키보드 범위를 검증하고 접근 가능한 일반 페이지 표 경로도 제공한다. 화면에 보이는 행만으로 전체 검색/선택/Excel 범위를 추정하지 않는다.

Starter의 [config.ts](../../frontend/apps/starter-app/src/config.ts)는 `VITE_SC_PATTERNS_ENABLED !== 'false'`를 사용한다. 비활성 빌드에서 App 메뉴·main.ts route 등록을 제외하고 `/patterns`는 `/`로 돌아간다. 실제 비활성 앱 브라우저는 optional chunk를 요청하지 않는다. 번들러가 해당 JS/CSS 2개를 출력하므로 완전한 번들 제거·별도 설치 가능한 패키지와 같다고 기록하지 않는다. 이는 011의 pack/빈 위치 생성·업그레이드 검증과 구분한다.

[007 요구사항 계약 조사](007-요구사항계약조사.md)는 후속 구현을 위한 읽기 검토 자료다. 사용자 actor DTO·업무 API·권한·revision·감사 adapter는 아직 구현 완료가 아니며 007~010에서 실제 확인한다. 원격 CI·Linux 시각 baseline·Docker daemon 실행·운영/Compose는 여전히 미검증이다.
