차트 내부 옵션은 단일 `uiTokens`로 생성한다. 선/막대·SVG renderer·범례·축·rich-text tooltip을 사용하며 부모의 readonly 자료를 변경하지 않는다. 빈 자료는 empty, 유한하지 않은 값은 오류로 구분한다. `prefers-reduced-motion`은 애니메이션에 반영하고 listener를 해제한다.

plot은 장식 영역으로 `aria-hidden`을 적용한다. 사용자는 figure 제목/설명과 native `details` 안의 caption·열/행 header를 가진 대체 표로 같은 값을 읽는다. 선택을 활성화하면 각 표 행의 실제 버튼이 클릭·Enter/Space 기본 동작으로 동일 `select` payload를 전달한다. 기본 조회용 차트의 plot 클릭은 이벤트를 만들지 않는다. resize와 unmount/dispose는 Vue ECharts의 실제 수명에 연결한다. [ECharts 크기와 수명](https://echarts.apache.org/handbook/en/concepts/chart-size/), [Vue ECharts autoresize](https://github.com/ecomfe/vue-echarts#props)

`class/style/title/lang/dir`·ARIA/data 등 공통 허용 attrs는 실제 figure에 전달한다. `role`과 자체 `aria-labelledby/describedby/busy`는 내부 의미를 유지하며 임의 ECharts/Vuetify attrs와 DOM callback을 전달하지 않는다. 집계·DTO 변환·기간/권한·Query·선택 후 업무 행동은 앱이 소유한다.

| Events / slots      | 공개 계약                                                                              |
| ------------------- | -------------------------------------------------------------------------------------- |
| `update:modelValue` | 편집 즉시 깊이 분리된 유효 `ScRichTextDocument`. readonly/disabled에서는 전달하지 않음 |

외부 ARIA label/description은 자체 label·hint·errors ID에 병합하여 native editor의 `role="textbox"`·`aria-multiline`에 연결한다. attrs만 바뀐 부모 렌더도 `onUpdated`의 attributes diff와 공식 `setOptions`로 반영한다. 일반 class/style/data는 wrapper가 받고 textbox의 role/상태/tabindex는 내부 계약이 소유한다. 임의 `$attrs`/vendor 옵션을 확장 설정으로 사용하지 않는다.

### JSON schema와 링크

```ts
interface ScRichTextDocument {
  readonly type: "doc";
  readonly content: readonly ScRichTextNode[];
}
// 자체 타입이며 Tiptap JSONContent를 재수출하지 않는다.
// 사용 예: {type:"doc",content:[{type:"paragraph",content:[{type:"text",text:"내용"}]}]}
```

`validateScRichTextDocument(value:unknown)`은 `{valid:true,document}` 또는 `{valid:false,message}`를 반환한다. 결과 document는 부모 자료와 깊이 분리된다.

| 영역        | 허용 규칙                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------------ |
| root        | 내용이 있는 `doc`; 비어 있는 입력은 `paragraph` 하나로 표현                                            |
| block node  | `paragraph`, `heading`, `bulletList`, `orderedList`; list 안은 `listItem`, listItem은 paragraph로 시작 |
| inline node | 비어 있지 않은 `text`, `hardBreak`                                                                     |
| attrs       | heading의 `level:1~6`; orderedList의 양의 정수 `start`만 허용                                          |
| text marks  | `bold`, `italic`, `underline`, `strike`, `code`, `link`; 중복 mark 금지                                |
| link attrs  | `href:string`만 공통 JSON에 포함. vendor target/rel 기본값은 내부 렌더 정책                            |
| 제한        | 10,000 node·중첩 32단계·text 누적 1,000,000자; 미지원 node/mark/속성 거절                              |

`isScSafeLink(href)`은 `http:`·`https:`·`mailto:`와 상대 경로/fragment/query를 허용한다. `javascript:`·`data:`·`file:` 등 다른 scheme, 제어문자/공백·backslash·앞뒤 공백·잘못된 절대 URL을 거절한다. 부모 JSON 검증과 StarterKit Link의 `isAllowedUri`에 같은 정책을 적용한다. autolink는 끄고 openOnClick은 false다. [Tiptap Link 설정](https://tiptap.dev/docs/editor/extensions/marks/link)

유효한 부모 교체만 `setContent(...,{emitUpdate:false})`로 반영하므로 update echo를 만들지 않는다. 잘못된 부모 JSON은 현재 editor draft를 보존하고 오류 event를 전달한다. 편집 중 검증 실패도 최근 유효 draft로 복구한다. `useEditor`가 unmount에서 destroy한다. 임의 HTML prop이나 `v-html` 경로는 추가하지 않는다. Tiptap 3의 `setContent`는 기본 emitUpdate가 true이므로 명시적인 false를 유지한다. [setContent 공식 API](https://tiptap.dev/docs/editor/api/commands/content/set-content)

Catalog의 local JSON draft는 즉시 갱신하고 blur에서 args로 commit한다. 이는 Controls fixture의 연결이며 업무 UI의 즉시 `update:modelValue` 계약을 바꾸지 않는다. 앱은 문서·dirty 상태·저장/권한/revision·서버 측 schema/링크 재검증을 소유한다. 저장/재조회·409의 입력 보존은 010에서 업무별로 검증한다.

## Excel adapter

```ts
type ScExcelCell = string | number | boolean | Date | null;
interface ScWorkbookColumn<TKey extends string = string> {
  key: TKey;
  label: string;
  type: "string" | "number" | "boolean" | "date";
}
// writeWorkbook({columns,rows,sheetName?,limits?}) → Promise<ArrayBuffer>
// readWorkbook(buffer,{columns,sheetName?,limits?}) → Promise<{rows,errors,sheetName}>
```

`writeWorkbook<TKey>`은 readonly columns와 `readonly Partial<Record<TKey,ScExcelCell>>[]`를 받고 입력 자료를 바꾸지 않는다. 기본 sheetName은 `자료`다. 문자열은 `=`, `+`, `-`, `@`로 시작해도 문자열 셀로 쓰며 formula 객체를 만들지 않는다. Date는 복제해 실제 날짜 셀로 쓴다. 잘못된 열/값/시트 이름은 TypeError, 제한 위반은 RangeError로 실패하며 파일 선택·다운로드·저장은 실행하지 않는다.

`readWorkbook<TKey>`은 ArrayBuffer/Uint8Array와 columns를 받고 `{rows:Record<TKey,ScExcelCell>[],errors:ScWorkbookError[],sheetName:string}`를 반환한다. 기본 첫 시트를 읽고 `sheetName`으로 지정할 수도 있다. header의 label·순서·열 개수가 정의와 정확히 같아야 한다. 빈 셀은 null, 완전히 빈 행은 제외한다. 값의 암묵적 문자열/숫자/boolean 변환을 하지 않으며 수식/공유 수식·hyperlink·rich text·Excel 오류 객체 셀을 거절한다. 유효한 행만 rows에 반환하고 오류는 원래 XLSX 행 번호로 누적한다.

| 제한 / 오류           | 실제 계약                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------ |
| `limits.maxRows`      | 기본 10,000 데이터 행, header 제외                                                               |
| `limits.maxColumns`   | 기본 100                                                                                         |
| `limits.maxFileBytes` | 기본 10 MiB, 입력 파일과 생성 파일 크기 검사                                                     |
| `ScWorkbookError`     | `{row:number,column?:string,code:string,message:string}`. header는 row 1, 파일 전체 오류는 row 0 |
| 파일/구조 오류        | `FILE_LIMIT`, `INVALID_FILE`, `MISSING_SHEET`, `SHEET_LIMIT`, `HEADER_MISMATCH`; 결과 rows 없음  |
| 셀 오류               | `FORMULA_NOT_ALLOWED`, `UNSUPPORTED_CELL`, `INVALID_VALUE`; 해당 행만 rows에서 제외              |

ExcelJS document Workbook의 `xlsx.writeBuffer/load`를 사용한다. 브라우저에서 Node 전용 readFile/writeFile·streaming API를 호출하지 않는다. 실제 입력 다운로드/선택·파일 취소·반영 승인·업무 Zod/schema·현재 page/선택/전체 범위·API 저장은 소비 앱의 책임이다. import 실패 때 기존 검토 자료를 교체하지 않는다. 행/열 검사는 document가 파싱된 뒤 수행하므로 압축 해제 메모리의 hard limit이나 대용량 streaming을 보장하지 않는다. 실제 서버 파일 처리/업무 저장·권한·rollback은 010 범위다. [ExcelJS 공식 README](https://github.com/exceljs/exceljs#browser)

### UUID 수정과 브라우저 번들의 범위

ExcelJS 전이 uuid가 초기 설치에서 moderate 2건으로 보고되었다. root override를 `uuid:11.1.1`로 지정하고 기존 lock 영향을 배제한 clean staging에서 lock 재해결·npm ci를 수행했다. 현재 의존성 audit는 [005-npm-audit-final.json](../검증/005-npm-audit-final.json)의 0건이다. Node document Workbook과 브라우저 XLSX 왕복은 각각 아래 실제 검증에서 확인했다.

ExcelJS `browser` 진입점은 패키지에 미리 포함된 `dist/exceljs.min.js`이며 npm override가 이 번들 내부 코드를 재작성하지 않는다. 번들에 남은 UUID 구현까지 새 버전으로 교체되었다고 기록하지 않는다. ExcelJS의 UUID 사용처는 conditional-format xform의 `v4()` 호출이며 외부 출력 buffer/offset을 전달하지 않는다. 이번 adapter는 그 UUID API를 공개하지 않는다.

공식 advisory는 출력 buffer를 받는 **v3/v5/v6 함수**의 bounds 검사 문제를 설명하며 v4는 해당 bounds 검사 동작을 구분한다. 현재 adapter의 v4 호출 경로와 실제 브라우저 왕복은 그 취약 동작을 사용하지 않는다는 판단이다. 이를 미리 빌드된 번들의 모든 보안 문제를 제거했다는 보장으로 확대하지 않는다. 앞으로 ExcelJS를 업그레이드하거나 다른 UUID/출력 buffer API를 사용하면 다시 검토한다. [공식 UUID advisory GHSA-w5hq-g745-h8pq](https://github.com/uuidjs/uuid/security/advisories/GHSA-w5hq-g745-h8pq)

## 다국어 factory

| 공개 API                                       | 계약                                                                                                                  |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `ScLocale`                                     | `'ko' \| 'en'`                                                                                                        |
| `ScMessageTree`                                | readonly 문자열 또는 중첩 문자열 객체                                                                                 |
| `commonMessages`                               | ko/en의 `common.*` 기본 메시지. locale 상태 없음                                                                      |
| `createScI18n({locale?,messages?,onMissing?})` | 매 호출별 Vue I18n plugin. locale 기본 ko·legacy:false·globalInjection:true·fallbackLocale:ko                         |
| `messages`                                     | `Partial<Record<ScLocale,ScMessageTree>>`. common 기본과 깊이 병합하며 원본 보존; 앱 메시지는 app.* 등 별도 namespace |
| `onMissing`                                    | `(locale:string,key:string)=>void`. 누락 언어/키 진단 callback; 기본 console 누락/fallback 경고는 끔                  |

공통 키는 `common.actions.{save,cancel,reset,retry,download,upload}`, `common.shell.{skipToContent,openNavigation,closeNavigation}`, `common.states.{loading,empty,error}`, `common.chart.{dataTitle,noData}`, `common.editor.{bold,italic,bulletList,undo,redo}`, `common.excel.{export,import}`다. 앱이 한국어/영어 메시지를 주입하고 필요한 UI label props에 `t()`를 연결한다. 앱별 인스턴스의 locale은 서로 영향을 주지 않는다. 중첩 32단계와 prototype 관련 키를 검사한다.

앱의 locale 선택·보관·`document.lang`·Vuetify locale 연결은 소비 앱이 맡는다. factory는 브라우저 저장소/Pinia·API DTO/상태 코드·Query·dirty 입력을 변경하지 않는다. Catalog는 preview에 factory를 설치하고 고유 fixture가 local scope locale/메시지를 사용하여 story 간 선택을 격리한다. [Vue I18n Composition](https://vue-i18n.intlify.dev/guide/advanced/composition)

## SFC 소비 예제

```vue
<template>
  <section aria-label="중립 확장 예제">
    <sc-chart :data="data" label="합성 수량" summary="조회 자료의 합성 예제" />
    <sc-rich-text-editor v-model="document" label="본문" :error-messages="errors" />
  </section>
</template>

<script setup lang="ts">
import { ref } from "vue";
import { ScChart, type ScChartDatum } from "@sc/ui/charts";
import { ScRichTextEditor, type ScRichTextDocument } from "@sc/ui/editor";
const data = ref<readonly ScChartDatum[]>([{ label: "첫 항목", value: 8 }]);
const document = ref<ScRichTextDocument>({ type: "doc", content: [{ type: "paragraph" }] });
const errors = ref<string[]>([]);
```
