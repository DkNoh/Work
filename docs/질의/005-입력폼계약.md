# 005 — 입력·폼·확인 대화상자 공개 계약

상태: **005 구현·로컬 통합 검증 완료**. 실제 추가된 다섯 UI의 focused 결과를 보존하고 두 앱/JAR·전체 Storybook·정적 Docs/Controls의 최종 결과를 함께 기록한다. 전체 단계와 명령·실패 기록의 원본은 [005 개발 문서](005-공통입력과화면패턴.md)다. 006 시각/수동 접근성·원격 CI와 011 외부 패키지 설치 검증은 별도다.

신규 공개 UI는 `ScSelect`, `ScCheckbox`, `ScTextArea`, `ScFormActions`, `ScConfirmDialog`다. 기존 `ScTextField`·`ScActionButton`·attrs 필터·디자인 토큰을 재사용하며 `ScDialog`·`ScFormField`를 이름만 다른 래퍼로 추가하지 않았다. 파일/import는 PascalCase, template는 `sc-select` 같은 kebab-case, SFC는 template → script setup lang="ts" → style 순서를 따른다. UI에는 VeeValidate/Zod/Query/Router·업무 API 의존성을 추가하지 않았다.

소비 앱은 공개 `@sc/ui` export를 사용한다. props와 옵션 속성/배열은 readonly다. 자식은 전달된 옵션·오류·model을 변경하지 않고 명시적인 emit으로 변경을 요청한다. `ScSelectSlots`, `ScCheckboxSlots`, `ScTextAreaSlots`는 내부 Vuetify slot을 외부에 노출하지 않는 빈 계약이다.

## 세 입력의 공통 props·이벤트

다음 기본값은 각 SFC의 실제 `withDefaults` 기준이다. `undefined`는 소비자가 주지 않았을 때 공통 UI가 별도 값을 지정하지 않는다는 뜻이다.

| Prop            | 타입                          | 기본값    | 동작                                                       |
| --------------- | ----------------------------- | --------- | ---------------------------------------------------------- |
| `label`         | string                        | 필수      | placeholder와 별도로 유지하는 필드 이름                    |
| `id`            | string                        | undefined | trim한 값, 또는 인스턴스별 자동 ID                         |
| `errorMessages` | string 또는 readonly string[] | `""`      | 빈 문자열만 제외하며 모든 나머지 오류를 표시               |
| `hint`          | string                        | `""`      | 포커스 상태의 입력 안내                                    |
| `required`      | boolean                       | false     | native required와 ARIA 상태. 업무 검증은 앱 schema가 담당  |
| `disabled`      | boolean                       | false     | native 비활성·자식 변경 차단                               |
| `readonly`      | boolean                       | false     | 포커스/탐색은 유지하고 자식 편집 차단                      |
| `name`          | string                        | undefined | native form 필드 이름                                      |
| `form`          | string                        | undefined | 외부 native form ID. Select의 별도 제출 DOM은 아래 표 확인 |
| `autofocus`     | boolean                       | false     | 내부 native 필드의 초기 포커스 요청                        |

세 입력의 공통 이벤트는 `focus(FocusEvent)`, `blur(FocusEvent)`, `keydown(KeyboardEvent)`, `keyup(KeyboardEvent)`다. disabled/readonly에서 차단하는 것은 model 편집과 입력 변경이다. readonly에서도 포커스·키보드 탐색 이벤트를 유지한다. native disabled 필드는 브라우저의 일반 포커스/편집 대상에서 제외된다.

### ScSelect

실제 구현: [ScSelect.vue](../../frontend/packages/ui/src/inputs/ScSelect.vue)

| Prop          | 타입                      | 기본값                    |
| ------------- | ------------------------- | ------------------------- |
| `modelValue`  | string 또는 null          | 필수                      |
| `options`     | readonly ScSelectOption[] | 필수                      |
| `placeholder` | string                    | undefined                 |
| `clearable`   | boolean                   | false                     |
| `loading`     | boolean                   | false                     |
| `emptyLabel`  | string                    | `선택할 항목이 없습니다.` |

`ScSelectOption`은 readonly `value: string`, `label: string`, `disabled?: boolean`이다. value는 배열 index가 아닌 안정적인 식별자로 지정한다. 단일 선택이며 객체 모델·multiple·임의 item renderer를 공개하지 않는다. loading은 표시 상태일 뿐 옵션 조회를 실행하지 않는다.

이벤트는 `update:modelValue(value: string | null)`, `change(value: string | null)`이다. change는 **선택 확정값**이며 native Event가 아니다. 같은 값·없는 옵션·disabled 옵션·문자열/null 외 값은 변경 emit하지 않는다. 부모의 외부 model 교체는 readonly/disabled에서도 표시한다. 옵션이 바뀌었다는 이유로 부모 model을 자동으로 초기화하지 않는다.

Vuetify `VSelect`에 옵션을 새 배열로 매핑한다. 각 item의 `props.disabled`와 `props["aria-disabled"]`를 함께 설정해 선택 불가 상태를 메뉴 option에도 표시한다. 부모 옵션을 직접 수정하지 않는다. Enter/Space·ArrowUp/Down·Home/End·Escape/Tab 선택/닫기 동작은 설치한 Vuetify 4.2.4가 담당하며, 실제 Chromium에서 Enter→End→Enter로 마지막 활성 항목을 선택하고 메뉴가 닫히는 것을 확인했다.

### ScCheckbox

실제 구현: [ScCheckbox.vue](../../frontend/packages/ui/src/inputs/ScCheckbox.vue)

추가 prop은 필수 `modelValue: boolean`이다. 이벤트는 `update:modelValue(value: boolean)`, `input(Event)`, `change(Event)`다. 배열 선택·true/false 임의 값·indeterminate는 공개하지 않는다. 내부 Vuetify true/false 모델은 boolean으로 고정한다.

Space로 체크를 전환한다. readonly에서 Space를 눌러도 기존 체크 상태와 포커스를 유지하며, disabled에서는 native input이 비활성화된다. 부모의 외부 boolean 교체는 표시한다. label slot 안에 내부 `${fieldId}-label` span을 생성하므로 외부 `aria-labelledby`와 병합할 때 실제 label ID가 존재한다.

### ScTextArea

실제 구현: [ScTextArea.vue](../../frontend/packages/ui/src/inputs/ScTextArea.vue)

| Prop                      | 타입                 | 기본값    |
| ------------------------- | -------------------- | --------- |
| `modelValue`              | string               | 필수      |
| `placeholder`             | string               | undefined |
| `autocomplete`            | string               | undefined |
| `maxLength` / `minLength` | number               | undefined |
| `inputMode`               | ScTextFieldInputMode | undefined |
| `rows`                    | number               | 4         |
| `autoGrow`                | boolean              | false     |
| `maxRows`                 | number               | undefined |

`ScTextFieldInputMode`는 none/text/decimal/numeric/tel/search/email/url이다. 이벤트는 `update:modelValue(string)`, `input(Event)`, `change(Event)`다. 문자열 모델을 유지하며 Enter는 줄바꿈이다. 길이 속성과 줄 수는 native 입력/표시 계약이며 업무 schema를 대신하지 않는다. readonly/disabled에서는 자식에서 프로그램 방식으로 전달한 model update도 차단하지만 부모 prop 교체는 그대로 표시한다.

Select/TextArea의 내부 표시 정책은 comfortable·outlined·primary다. attrs로 density/variant/color를 우회할 수 없다. 테두리·placeholder·radius·motion은 공통 토큰을 사용한다. Checkbox의 긴 label은 줄바꿈하고 기본 미체크 경계 색도 토큰을 사용한다.

## 입력 attrs·ID·오류·native form

모든 입력은 `inheritAttrs: false`와 기존 `pickScHtmlAttrs` 정책을 사용한다. `useAttrs`를 computed에 캐시하지 않고 render마다 내부 `fieldAttrs()`가 읽으므로 ARIA/data만 갱신한 경우도 반영한다. 공통 허용 attrs는 class/style/title/lang/dir/tabindex·유효한 aria-*·data-*다. native name/form/autofocus 및 TextArea 입력 속성은 명시적인 prop으로 전달한다. 임의 Vuetify props나 callback은 전달하지 않는다.

| 부품     | 실제 attrs/값 대상                                                                                                 | Native FormData                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| Select   | class/style/data-*는 바깥 `.sc-select`; ARIA·tabindex는 이름 있는 실제 input. name/form/선택값은 별도 hidden input | label 대신 문자열 ID 제출. null이면 값 없음. disabled일 때 hidden input name을 지정하지 않아 제외 |
| Checkbox | class/style/data-*는 바깥 `.sc-checkbox`; name/form·ARIA는 실제 checkbox input                                     | 체크된 경우 `"true"`; unchecked/disabled이면 필드 제외. readonly 값은 제출                        |
| TextArea | class/style/data-*는 바깥 `.sc-text-area`; name/form·입력 속성·ARIA는 실제 textarea                                | 원래 여러 줄 문자열 제출. disabled 제외, readonly 값 제출                                         |

`role`, `aria-invalid/required/disabled/readonly`, `aria-describedby/labelledby`를 임의 attrs로 덮어쓰지 못하게 한다. Select는 내부 `aria-controls/expanded/haspopup/autocomplete`, Checkbox는 `aria-checked`도 예약한다. 외부 `aria-describedby` 문자열은 내부 오류/포커스 hint의 `${fieldId}-messages`와 중복 없이 병합한다. 외부 `aria-labelledby`도 내부 `${fieldId}-label`과 병합한다.

자동 ID는 각각 `sc-select-${useId()}`, `sc-checkbox-${useId()}`, `sc-text-area-${useId()}`다. 실제 앱별 ID prefix는 `createScVuetify()`의 기존 CSR 정책을 사용한다. 별도 앱/번들의 ID·SSR 범위는 [기존 공개 계약](UI-공개계약.md)을 따른다. 오류는 부모 readonly 배열을 복사해 빈 문자열을 제외하며, 내부 `max-errors`를 전체 오류 개수로 지정한다. Vuetify 기본 한 건 표시로 잘리지 않도록 실제 두 오류의 DOM/접근성 설명을 검사했다.

폼 값·dirty/touched·schema·서버 오류·저장 중 상태는 소비 폼이 소유한다. VeeValidate `useForm/defineField`의 모델을 UI에 연결하고 Zod 4 `safeParse` 결과를 직접 field error로 설정한다. 저장은 parsed.data를 사용하고 400/409 실패에서 입력을 reset하지 않는다. 현재 한 필드 create/edit의 중복만으로 generic form bridge를 추가하지 않았다. 별도 폼 상태를 복사하는 공통 저장 훅도 없다.

## ScFormActions

실제 구현: [ScFormActions.vue](../../frontend/packages/ui/src/forms/ScFormActions.vue)

| Prop                | 타입    | 기본값     |
| ------------------- | ------- | ---------- |
| `busy` / `disabled` | boolean | false      |
| `submitLabel`       | string  | `저장`     |
| `cancelLabel`       | string  | `취소`     |
| `busyLabel`         | string  | `저장 중…` |
| `showCancel`        | boolean | true       |
| `form`              | string  | undefined  |

이벤트는 `cancel(event: MouseEvent)` 하나다. submit emit을 만들지 않으며 기본 ScActionButton의 **실제 type="submit"** 버튼이 부모 native form을 제출한다. 취소는 type="button"이며 제출/자동 reset을 하지 않는다. 외부에 배치하면 form prop으로 부모 form ID를 지정한다. busy/disabled에서 기본 제출·취소가 비활성화되고, 기존 버튼의 같은 렌더 주기 클릭 방어를 재사용한다.

| Slot        | 계약                                                                              |
| ----------- | --------------------------------------------------------------------------------- |
| `notice`    | 설명·저장 상태 VNode[]. 기본 버튼과 함께 배치                                     |
| `secondary` | 추가 행동 VNode[]. 기본 제출/취소를 교체하지 않으며 권한·busy 제어는 소비 폼 책임 |

attrs는 실제 바깥 div로 전달하며 공통 HTML/ARIA/data와 id를 허용한다. 내부 `aria-busy`는 prop이 원본이고 loading/theme/tag 같은 내부 옵션은 전달하지 않는다. 컴포넌트는 추가 form을 만들지 않는다. 검증·저장·취소 확인·reset 함수는 부모가 실행한다.

## ScConfirmDialog

실제 구현: [ScConfirmDialog.vue](../../frontend/packages/ui/src/forms/ScConfirmDialog.vue)

| Prop           | 타입                    | 기본값      |
| -------------- | ----------------------- | ----------- |
| `modelValue`   | boolean                 | 필수        |
| `title`        | string                  | 필수        |
| `message`      | string                  | `""`        |
| `confirmLabel` | string                  | `확인`      |
| `cancelLabel`  | string                  | `취소`      |
| `busyLabel`    | string                  | `처리 중…`  |
| `busy`         | boolean                 | false       |
| `intent`       | `"default" \| "danger"` | `"default"` |
| `id`           | string                  | undefined   |

| Event               | Payload                              | 실제 정책                                                                         |
| ------------------- | ------------------------------------ | --------------------------------------------------------------------------------- |
| `confirm`           | 없음                                 | 자동으로 닫지 않는다. 부모가 저장/삭제·busy·성공 시 model false·실패 시 유지 결정 |
| `cancel`            | `"button" \| "escape" \| "backdrop"` | 사용자 취소 이유 전달                                                             |
| `update:modelValue` | boolean                              | 취소 시 false 닫기 요청. 실제 닫힘은 부모 model 반영 후                           |

`default` slot은 message 뒤의 추가 안내 VNode[]다. 내부 기본 확인/취소 버튼을 대체하지 않는다. title/description·열림 상태·busy를 임의 attrs로 우회할 수 없다. 공통 class/style/HTML/ARIA/data는 실제 native dialog에 전달하되 role/tabindex/aria-modal/aria-label/aria-labelledby/describedby/busy는 예약한다. native dialog의 모달 의미를 유지하며 id는 trim한 prop 또는 `sc-confirm-dialog-${useId()}`다. title ID는 `${dialogId}-title`, message ID는 `${dialogId}-message`이고 message가 있을 때만 설명으로 연결한다.

부모 model true를 DOM 연결 후 showModal에 반영한다. 열기 직전 호출 요소를 기록하고 초기 포커스는 취소 버튼에 둔다. busy로 취소 버튼이 비활성화된 경우 dialog로 이동한다. Tab/ShiftTab은 보이는 활성 제어 사이에서 순환하고 제어가 없으면 dialog에 유지한다. Escape의 기본 닫기와 native cancel은 차단한 뒤 공통 취소 정책을 적용한다. dialog 본문 경계 밖 클릭만 backdrop 취소로 취급한다.

busy 동안 확인·취소 버튼·Escape·native cancel·backdrop의 사용자 행동을 모두 막는다. 부모가 model false로 명시적으로 닫는 것은 busy 중에도 허용한다. 확인/취소의 같은 렌더 주기 재진입도 nextTick까지 방어한다. 닫히거나 열린 채 unmount되면 native dialog를 close하고, 연결돼 있고 disabled/inert가 아닌 호출 요소에 focus를 복귀한다. 호출 요소가 제거된 업무 화면의 대체 포커스는 앱이 소유한다. 공통 부품은 Route guard·미저장 판단·API·업무 권한을 실행하지 않는다.
