# 005 — 공통 표와 가상화 공개 계약

상태: **005 구현·로컬 통합 검증 완료**. 아래 6개 단위와 8개 focused Chromium Story 결과를 보존하며 두 소비 앱·최신 JAR·81개 전체 Story·정적 Docs/Controls·실측 수치도 최종 확인했다. [005 전체 기록](005-공통입력과화면패턴.md)에 명령·초기 실패·최종 결과가 있다. 009의 복잡 SQL·권한/count·실제 서버 대규모 자료 검증을 이 단계의 합성 자료 검사로 대체하지 않는다.

## 모듈과 버전

공개 경로는 `@sc/ui/table`이다. [공개 barrel](../../frontend/packages/ui/src/table/index.ts)은 `ScDataTable`, `ScVirtualTable`, `ScVirtualList`와 `Sc` 공개 타입만 내보낸다. [contracts.ts](../../frontend/packages/ui/src/table/contracts.ts)가 Props/Emits/Slots의 원본이다. 내부 [model.ts](../../frontend/packages/ui/src/table/model.ts)는 Table 모델을, [useVirtualRows.ts](../../frontend/packages/ui/src/table/useVirtualRows.ts)는 가상 범위·측정·키 기반 스크롤/포커스를 담당한다. 앱의 API·Router·Query·세션·권한 코드를 import하지 않는다.

| 항목                    | 실제 직접 버전                                                      | 계약                              |
| ----------------------- | ------------------------------------------------------------------- | --------------------------------- |
| `@tanstack/vue-table`   | 9.2.6                                                               | Node ≥20, Vue ≥3.2, MIT           |
| `@tanstack/vue-virtual` | 3.13.39                                                             | Vue ^2.7 또는 ^3, MIT             |
| 현재 검증 환경          | Node 24.16.0, Vue 3.5.43, TS 5.9.3, Vuetify 4.2.4, Storybook 10.4.1 | workspace manifest·단일 lock 기준 |

실제 설치 뒤 UI와 Catalog 타입 검사를 통과했다. MIT 원래 고지는 설치된 패키지의 LICENSE와 함께 유지한다. [Table 배포 메타데이터](https://registry.npmjs.org/@tanstack/vue-table/9.2.6), [Virtual 배포 메타데이터](https://registry.npmjs.org/@tanstack/vue-virtual/3.13.39)

현재 Table `/latest`는 v9이다. 구현은 `useTable/tableFeatures/createSortedRowModel/createPaginatedRowModel`을 사용하며 v8의 `useVueTable/getCoreRowModel` API를 혼용하지 않는다. `useVirtualizer(computed(options))`의 실제 반환은 `Ref<Virtualizer>`이므로 script에서 `.value`로 접근한다. 공개 API에는 vendor 타입·전체 options를 노출하지 않는다. [v9 Vue 시작 가이드](https://tanstack.com/table/latest/docs/framework/vue/quick-start), [Vue Virtual](https://tanstack.com/virtual/latest/docs/framework/vue/vue-virtual)

화면은 SFC의 `<template>` → `<script setup lang="ts">` → `<style scoped lang="scss">`로 작성한다. native HTML과 `v-for`·slot을 사용하고 `h`·JSX·TSX·`FlexRender`·렌더 함수형 셀 계약을 도입하지 않는다. 파일/import는 PascalCase `Sc...`, template 태그는 `sc-...`, CSS는 `.sc-*`, props는 camelCase/속성은 kebab-case를 따른다.

## ScDataTable Props

`ScDataTable<T>`와 `ScVirtualTable<T>`의 행은 객체 타입이다. 배열과 열은 readonly 입력이며 UI가 변경하지 않는다.

| Prop              | 타입·기본값                                                | 책임                                                                                           |
| ----------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `rows`            | 필수 `readonly T[]`                                        | client는 처리할 전체 자료, server는 이미 정렬/페이지 처리된 현재 응답                          |
| `columns`         | 필수 `readonly ScTableColumn<T>[]`                         | 자체 `{ id, label, value(row), sortable? }`; value는 문자열/숫자/boolean/null/undefined만 반환 |
| `caption`         | 필수 string                                                | native table의 접근성 이름과 표시 제목                                                         |
| `getRowKey`       | 필수 `(row) => string`                                     | 지속적인 업무 ID. 빈 문자열·중복 키를 거절하며 index를 대신 만들지 않음                        |
| `getRowLabel`     | 선택 함수                                                  | 선택 checkbox/radio의 행 이름. 생략하면 업무 ID                                                |
| `dataMode`        | `client` 기본, 또는 `server`                               | 정렬/페이지 처리 위치를 명시                                                                   |
| `sorting`         | 기본 null, 또는 `{ columnId, direction: 'asc' \| 'desc' }` | 부모가 소유하는 단일 열 정렬                                                                   |
| `pagination`      | 선택 `{ pageIndex, pageSize, total }`                      | 0-based index. 생략하면 일반 표의 페이지 컨트롤을 표시하지 않음                                |
| `selectionMode`   | `none` 기본, `single`, `multiple`                          | native radio/checkbox 표시                                                                     |
| `selectedKeys`    | 기본 빈 readonly string 배열                               | 부모가 소유하는 선택 ID; 정렬/페이지 전환으로 삭제하지 않음                                    |
| `isRowSelectable` | 선택 함수, 생략 시 true                                    | 업무 판단을 앱에서 전달. 서버 권한 검사 대체 아님                                              |
| `loading`         | 기본 false                                                 | `aria-busy`·상태 안내·정렬/선택/페이지/retry 제한                                              |
| `error`           | 선택 string                                                | 오류 표시와 retry 요청. 기존 행과 선택을 유지                                                  |
| `labels`          | 선택 `Partial<ScTableLabels>`                              | 앱 locale 메시지 주입. 누락/undefined는 한국어 기본값                                          |

열 ID도 빈 값·중복을 거절한다. pagination은 `pageIndex/total`이 0 이상의 정수이고 `pageSize`가 양의 정수여야 한다. 현재 페이지가 삭제 이후 전체 페이지 범위를 벗어난 경우의 URL 보정은 앱이 결정한다.

client 모드는 TanStack 모델이 정렬/페이지를 계산하며 전체 건수는 `rows.length`다. server 모드는 `manualSorting/manualPagination`으로 전달 자료를 다시 정렬하거나 나누지 않고 `pagination.total`을 사용한다. server에서 pagination을 생략하면 전달받은 자료를 그대로 표시하며 전체 서버 건수를 안다고 주장하지 않는다.

정렬 버튼은 오름차순 → 내림차순 → 해제 순으로 요청한다. 정렬 요청 자체가 Router 페이지를 초기화하지 않는다. 앱이 정렬/검색/size 변경과 `pageIndex=0` 전환을 함께 결정한다.

## 이벤트와 Slots

| 이벤트                | Payload               | 처리                                       |
| --------------------- | --------------------- | ------------------------------------------ |
| `change-sort`         | `ScTableSort \| null` | 부모가 새 정렬을 반영하거나 서버 요청 수행 |
| `change-pagination`   | `ScTablePagination`   | 부모가 URL·Query를 갱신                    |
| `update:selectedKeys` | 새로운 string 배열    | props를 변경하지 않고 선택 변경 요청       |
| `retry`               | 없음                  | 부모의 Query 재조회                        |

single 선택은 새 ID 하나로 교체한다. multiple의 전체 선택은 **현재 전달된 자료 중 선택 가능한 행**에만 적용한다. 일반 client 페이지 표는 현재 표시 페이지를 대상으로 한다. 다른 서버 페이지의 선택 ID는 유지하며, 서버의 미조회 전체 결과를 선택하는 기능은 제공하지 않는다. 선택 여부는 props에서 계산한 Set으로 확인하므로 10,000개 선택의 체크 상태를 중첩 배열 탐색으로 계산하지 않는다.

| Slot               | 전달 값                                      | 책임                                             |
| ------------------ | -------------------------------------------- | ------------------------------------------------ |
| `cell`             | `{ row, rowKey, rowIndex, columnId, value }` | 셀 내부 SFC 콘텐츠. 기본은 값의 텍스트 표시      |
| `row-actions`      | `{ row, rowKey, rowIndex }`                  | 앱 행동·권한·버튼 이름. 제공하면 행 동작 열 생성 |
| `loading`, `empty` | 없음                                         | 공통 상태 안내 내부 콘텐츠                       |
| `error`            | `{ message, retry }`                         | 오류 안내 내부 콘텐츠와 재조회 행동              |

전체 `<tr>`나 `<table>`를 교체하는 slot은 제공하지 않는다. caption·header·row key·선택 구조는 공통 UI가 보존한다. 앱 slot의 버튼은 `type="button"`과 구체적인 접근성 이름을 제공한다. 행동 종류가 동적으로 바뀌는 경우 `data-sc-focus="open"`처럼 지속적인 행동 토큰을 붙일 수 있다.

## attrs와 native 의미 구조

세 부품 모두 `inheritAttrs: false`다. 공통 whitelist의 class/style/title/lang/dir/tabindex·ARIA/data 및 id는 바깥 div에 전달한다. role과 `aria-busy`는 제외하며 내부 표를 임의 grid로 바꿀 수 없다. 내부 Vuetify 옵션·이벤트·등록하지 않은 callback은 자동 전달하지 않는다.

`ScDataTable`만 바깥 div에 `onFocusin/onFocusout/onKeydown/onKeyup` native 이벤트 listener를 허용한다. Virtual 두 부품은 공개 이벤트와 slot 내부 listener만 지원한다. 내부 viewport/table/input에 임의 attrs를 분산 전달하지 않는다.

일반 표는 native `table/caption/thead/th scope="col"`이며 정렬 가능한 header에 `aria-sort`와 native 정렬 버튼을 사용한다. 행·셀에 별도의 roving tabindex를 넣지 않는다. native checkbox/radio·행동 버튼과 가로 스크롤 region이 Tab으로 접근 가능하다. header는 스크롤 영역에서 sticky로 유지한다. [WAI Table pattern](https://www.w3.org/WAI/ARIA/apg/patterns/table/)

## ScVirtualTable과 ScVirtualList

`ScVirtualTable`은 위 표 계약을 확장하며 `ScVirtualList`는 별도의 native 목록 계약을 가진다. 표와 목록의 HTML 의미 구조는 각 SFC가 유지하고 내부 가상 범위/측정 엔진만 공유한다.

| 공통 가상화 Prop    | 기본값 | 제한                                                        |
| ------------------- | ------ | ----------------------------------------------------------- |
| `height`            | 480px  | 양의 유한한 viewport 높이                                   |
| `estimateRowHeight` | 48px   | 양의 유한한 최소 행 높이/초기 추정치; 실제 가변 높이를 측정 |
| `overscan`          | 8      | 양쪽 추가 렌더 개수, 0~20 정수                              |

`ScVirtualList`의 추가 필수 props는 readonly `items`, `label`, `getItemKey(item)`다. 선택 `getItemLabel`은 탐색 버튼의 이름이며 생략하면 키를 사용한다. loading/error/labels와 `retry` 이벤트를 제공한다. `item` slot은 `{ item, itemKey, index }`를 받고 loading/empty/error slot은 표와 같은 상태 책임을 갖는다. 목록 선택이 필요하면 앱이 item slot의 native checkbox와 선택 ID를 소유한다.

- VirtualTable은 normal-flow native table과 숨긴 spacer row를 사용한다. `display:grid/flex`로 table/tr 의미를 바꾸지 않는다. 10,000개 자료·header 한 행의 `aria-rowcount`는 10001이며 데이터 행 `aria-rowindex`는 전체 행 위치+2다. server 모드의 위치에는 현재 페이지 offset을 포함한다. [부분 렌더링 표 속성](https://www.w3.org/WAI/ARIA/apg/practices/grid-and-table-properties/)
- VirtualList는 native `ul/li`와 명시적인 list 의미, 각 항목의 `aria-posinset/index+1`·`aria-setsize/items.length`를 제공한다. spacer는 접근성 트리에서 숨긴다. [WAI-ARIA 목록 위치](https://www.w3.org/TR/wai-aria-1.2/#aria-posinset)
- `getItemKey`는 정렬된 현재 행 모델의 지속적인 ID다. 현재 포커스 행 **하나**만 range에 추가하며 모든 선택 행을 DOM에 고정하지 않는다. vendor memo에 pin 변경이 반영되도록 focused index를 options computed에서 읽는다.
- 행 ResizeObserver 측정은 animation frame에 연결한다. 표 caption/header의 실측 높이는 scroll margin에 반영하고 Observer를 해제한다. Vue adapter의 scope disposal과 컴포넌트의 해제 처리를 유지한다.
- 표의 첫/이전/다음/마지막 행 버튼은 native 선택/행동 컨트롤을 대상으로 이동한다. 행동이 없는 static 셀을 임의 focusable grid cell로 바꾸지 않는다. 현재 행 위치는 status로 안내한다.
- 목록의 탐색 버튼에만 ArrowUp/ArrowDown/Home/End를 적용한다. item slot 내부 input/select/editor의 키를 가로채지 않는다.

두 가상 부품은 `ScVirtualHandle`의 `scrollToKey(key): boolean`과 `focusRow(key): Promise<boolean>`을 공개한다. 존재하지 않는 키는 false다. focusRow는 실제 native 컨트롤 포커스 여부를 반환한다. 해제 이후에는 이동하지 않는다.

controlled 정렬로 순서가 바뀌면 현재 포커스 ID의 새 위치를 찾아 스크롤하고 같은 행동 토큰으로 복원한다. 별도 토큰이 없으면 해당 행의 native 컨트롤 순서를 사용한다. 같은 ID의 자료 교체에서는 keyed DOM과 실제 높이 측정으로 포커스를 보존한다. 키가 제거되면 viewport로 포커스를 복귀한다. 앱이 slot 컨트롤 자체를 제거하거나 업무 권한·입력 상태를 바꾸는 전환은 앱의 행동/후속 포커스 책임이다. [Virtualizer key/range/scroll API](https://tanstack.com/virtual/latest/docs/api/virtualizer)

## 일반 페이지 표 대안

VirtualTable에는 실제 `ScDataTable`로 전환하는 버튼이 있다. 정렬·선택 ID·열·상태·slots를 공유한다. client 대안은 기본 20행씩 표시하는 내부 보기 전용 page를 갖고 선택/현재 ID가 있는 페이지로 이동한다. 이 내부 page는 업무 Router/Query 상태의 복사본이 아니다. server 대안은 부모의 pagination과 `change-pagination`을 그대로 사용한다.

일반 보기에서도 공개 scrollToKey/focusRow가 같은 ID를 찾는다. 가상 보기로 복귀하면 현재 키의 위치와 선택을 유지한다. 전환 시 포커스를 옮길 native 행 컨트롤이 없으면 전환 버튼에 포커스를 유지한다.

가상화는 렌더된 subset의 의미 정보를 제공하며 전체 문서 찾기·모든 스크린리더 탐색이 일반 표와 같다고 주장하지 않는다. 일반 페이지 표 대안을 실제로 이용할 수 있다. axe 통과를 수동 스크린리더 검증 완료로 기록하지 않는다.

## 앱과 서버의 상태 원본

Router query는 page/size/sort/filter의 원본, Vue Query는 서버 자료/요청 상태의 원본이다. 앱이 정렬·페이지 이벤트를 받아 URL과 Query key를 갱신하고 runtime의 단일 HTTP client를 사용한다. 선택 ID·권한·행 행동·저장 전 입력과 409 보존도 앱이 소유한다. UI는 Query·Pinia·HTTP 요청을 만들지 않는다.

현재 `/api/examples`는 page/size와 기본 ID 내림차순 계약을 가진다. 새 정렬/검색을 지원하는 서버 계약으로 확장하기 전에는 해당 열을 sortable로 표시하지 않는다. 현재 서버 페이지를 client에서만 정렬하고 전체 서버 정렬처럼 설명하지 않는다. 009의 복잡 MyBatis 조회는 SQL allowlist·권한·count·page·성능과 함께 검증한다. 가상화는 서버 데이터 처리/전송/메모리 비용을 없애지 않는다. [페이지네이션 경계](https://tanstack.com/table/latest/docs/framework/vue/guide/pagination)

## 006 접근성 후속 변경

실제 JAR full-document axe에서 목록 제목과 스크롤 region의 동일 이름을 발견했다. `ScVirtualList`의 viewport region은 기본 `${label} 스크롤 영역`으로 목록의 접근성 이름과 구분한다. 공개 `ScTableLabels.listScrollRegion?: (label: string) => string`을 추가했으며 생략한 기존 소비 코드는 한국어 기본 이름을 사용한다. 두 앱의 locale별 labels는 영어에서 `${label} scroll area`를 전달한다. label·목록 항목/위치·키보드 탐색 계약은 유지한다.
