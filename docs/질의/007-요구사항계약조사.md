## 이미지 버전·0..1 박스·파일 계약: 010 구현

## 순차 구현·검증 목록

1. 실제 source JSON/URL/권한 표를 기준으로 007 DTO·OpenAPI·Reference 업무 패키지/폴더·H2 migration과 사용자 인증 경계를 정한다. 공통 UI/runtime는 업무를 import하지 않는다. 이후 문서·명세·생성 타입·SPA route를 함께 추가한다.
2. 합성 H2 사용자/활성·보관 메뉴로 작성자 A, 지정 검토자 B, 미지정 REVIEWER C, ADMIN D를 준비한다. 비밀번호는 새 임시 secret에만 두고 원본 계정을 사용하지 않는다.
3. 일반 요청의 목록·상세·create/update·필드 오류/409·초안 가시성을 구현한다. 목록과 count 동일 조건, literal `%/_/backslash`, 초기revision1·stale revision·실제 동시 @Version 충돌을 검사한다.
4. 담당자 변경/동일값/해제·제출·보완→수정→재제출·검토·합의를 구현하고 역할/작성자/담당자/상태 조합을 HTTP에서 검사한다. 합의 필수 범위와 동일담당자 no-op를 포함한다.
5. 댓글/변경 이력·Day.js 시각·보안 감사 adapter를 추가한다. 댓글은 revision/다른 탭 초안을 유지, 변경과 이력은 함께 rollback, 거절/실패 감사의 민감값 제외를 검사한다.
6. Sc 입력·ScDataTable·ScListDetailLayout·ScConfirmDialog로 업무 폼을 조립한다. 서버 자료는 Query, 상세 ID/filter/page는 Router, 폼 초안은 VeeValidate 원본으로 유지한다. API는 runtime 단일 client를 사용한다.
7. 새 JAR와 합성 H2로 작성자↔검토자 흐름의 실제 E2E를 실행한다. 새 step 명령/성공/실패/미확인을 기록하고 아래 미확인 항목이 남으면 007 완료로 표시하지 않는다.

필수 실패 검사에는 다음을 포함한다.

- 비작성자의 DRAFT 목록/count·상세 거절; ADMIN 조회 가능하지만 타인 본문 PUT/submit/agree 거절; 미지정 ADMIN/C의 review 거절.
- 담당자 없는 submit 허용·review 거절; 본인 담당자 지정 거절; 담당자 변경 시 현재Review 제거/이력 보존/상태복귀, 같은값은 revision 그대로.
- 일반 요청 screenVersionId/annotation 쌍 오류, 불변 screenVersionId와 숫자 비정상 좌표의 API 경계는 010 구현 시 추가한다. 007 일반 입력에서 임의 author/status/시각 JSON 필드 거절은 즉시 검사한다.
- 400/403/409/500·세션 전환·늦은 응답에서 초안 보존. A저장/재조회 응답이 선택B의 값/오류를 덮지 않음. failed refetch의 stale cache로 `resetForm`하지 않음.
- 같은 상세의 자동 재조회·언어 변경이 dirty 본문/검토/댓글을 덮지 않음. route 취소 시 URL/입력 유지, 승인 시 실제 이동, 로그아웃/401에서 보호 화면에 걸리지 않고 pending 확인 Promise 정리.
- 검토 입력의 rationale 필수·각 길이/enum·needsInfo 명령과 decision 차이, POSSIBLE/CONDITIONAL 외 합의 거절, 빈 scope/exclusions/acceptance 합의 거절.
- JAR 직접 `/requests/{id}`·새로고침·없는 API/asset 오류, OpenAPI/생성 타입·실제 JSON의 필드/숫자flag/null/요약·상세 구분.

현재 확인 상태는 **문서·소스 정적 조사 완료**다. 007 신규 소스·H2 schema·업무 사용자/auth adapter·Day.js·감사·업무 E2E는 아직 이 문서로 구현/실행한 것이 없다. 010 이미지/파일·칸반·관리·업무 확장 완료도 주장하지 않는다.
