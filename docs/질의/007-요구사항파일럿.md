# 007 요구사항 파일럿·사용자·날짜·보안 감사

상태: **구현·로컬 통합 검증 완료**. 독립 Reference에 사용자·일반 요구사항·날짜·보안 감사를 구현했다. 모바일 목록의 최종 시각 수정 이후 fresh 두 JAR·서버52·unit108/23 files·8 workspace+E2E 타입·JAR E2E41·fullDOM axe52회·업무6장 실제 이미지 검토까지 확인했다. 008~012는 대기이며 운영/외부 배포·수동 음성 검증을 완료로 표시하지 않는다.

원본 WorkboardVue 실행 소스·SQLite·DB·업로드·비밀번호·`.runtime`은 레퍼런스로 유지한다. 신규 기준은 Vue3 SFC·`Sc`/`sc-*` 공통 UI·Spring Boot/JDK21·H2·JPA/MyBatis·Swagger/OpenAPI·OpenFeign이다. Redis·JWT·SSO는 제외하고 서버 세션·CSRF를 유지한다. 전체 조건부 기술의 구현·예제·기능 검증 범위와 소비 앱 활성 선택은 바뀌지 않는다. [007 조사](007-요구사항계약조사.md), [서버 설계](007-서버설계.md), [검증 matrix](007-서버검증계획.md)를 입력 자료로 사용한다.

## 세 가지 명세와 앱별 생성 타입

`npm run api:generate`는 셋을 생성하고 `npm run api:check`는 각각 승인 snapshot과 일치하는지 확인한다. `npm run api:check-server`는 Reference와 Starter의 격리된 dev JAR 명세를 각각 비교한다. live 검사는 환경별 server URL만 `/`로 정규화하며 schema·operation·보안·required/null/숫자 enum을 지우지 않는다. intentional update와 타입 생성은 실제 HTTP/schema 검증을 대신하지 않는다.

앞선 API capture JAR는 서버 명세 추출을 위한 early package이며 006 프런트 산출물이 포함되어 있었다. 이를 007 업무 UI/JAR 완료로 기록하지 않는다. 최종 Vue 빌드·fresh JAR·metadata/실제 JSON을 아래 후속 통합으로 확인했다. OpenAPI 3.1의 숫자 flag `0/1`·nullable ref·required와 원본 응답 key를 실제 DTO/JSON에 맞추어 검증한다.

## 기본 me 확장과 DB 사용자

공통 [CommonEndpoints](../../backend/framework-autoconfigure/src/main/java/dev/scframework/autoconfigure/web/CommonEndpoints.java)는 health/CSRF만 소유한다. [DefaultSessionEndpoints](../../backend/framework-autoconfigure/src/main/java/dev/scframework/autoconfigure/web/DefaultSessionEndpoints.java)가 기본 me의 `username,roles[]`를 반환한다. `sc.framework.session-endpoint.enabled` 기본 true를 false로 하면 me만 비활성화하며 Security chain·로그인·CSRF는 유지한다. 소비 기본 endpoint·encoder·UserDetailsService·chain·Clock·audit sink는 missing-bean backoff로 교체한다. bean overriding이나 provider-only 지원을 새 계약으로 주장하지 않는다.

Reference는 기본 me를 끄고 [UserController](../../backend/reference-app/src/main/java/dev/scframework/reference/identity/UserController.java)의 me 하나가 원본 `{id,username,displayName,role}`을 반환한다. `reference_user`의 numeric ID/현재 DB 역할이 작성자·담당자·ADMIN 판단의 원본이며 오래된 세션 authority를 업무 권한의 최종 판단으로 사용하지 않는다. `ActorResolver`는 anonymous 인증을 거절하고 현재 DB 사용자를 다시 읽는다. 사용자 응답·메뉴·요구사항 JSON에 password/hash를 포함하지 않는다.

Reference DB가 비어 있을 때만 앱 UserService bootstrap이 기존 `SecretFileUsers.load(...).loadUserByUsername(...).getPassword()`의 **encoded hash**를 재사용해 최초 ADMIN을 만든다. 새로운 원문 반환 helper나 중복 BCrypt를 만들지 않는다. 기존 파일 존재·600 모드·username·16..72 UTF-8 검증은 그대로 사용한다. 기존 DB 재기동에서는 사용자/ID/hash를 다시 쓰지 않는다. ApplicationRunner 전에 health를 UP로 노출하지 않도록 Boot readiness가 ACCEPTING_TRAFFIC 전이면 503/STARTING, 준비 후 기존200/UP를 반환한다. 신규 일반 사용자 API의 최소12자·UTF-8최대72바이트와 bootstrap 최소16바이트는 다른 계약이다.

프런트 runtime의 `createFrameworkRuntime<TIdentity>`는 `decodeIdentity(unknown)` 확장점을 제공한다. 기본 Starter는 기존 username/roles decoder를 사용하고, Reference [auth/identity.ts](../../frontend/apps/reference-app/src/auth/identity.ts)가 numeric ID·displayName·role을 검증한 뒤 하나의 runtime identity에 연결한다. `roles:[role]`는 runtime 내부 호환값이며 서버 User JSON에 추가하지 않는다. 계정 사본·별도 Axios·별도 me 요청을 만들지 않고 기존 generation/401/Query·CSRF 초기화/이전 응답 폐기를 유지한다.

## 요구사항 업무와 상태 원본

Reference [features/requirements](../../frontend/apps/reference-app/src/features/requirements)는 앱 생성 DTO/API·Query keys·Zod 입력 schema·권한·본문/검토/댓글/이력·페이지를 소유한다. URL/선택·page/filter는 Router, 서버 자료는 Vue Query, 초안/오류/dirty는 해당 폼이다. 공통 UI나 Pinia에 업무 원본을 다시 만들지 않는다.

본문과 검토는 각각 baseline revision/resetKey를 가지며 동일 시각 또는 같은 상태의 유효한 명령에서도 DB revision이 한 번 증가해야 한다. 새로고침/늦은 A 응답/선택 B/세션 교체/400·409·500이 작성 중 입력을 덮지 않아야 한다. 댓글 응답을 본문 입력 초기화로 사용하지 않는다. 미저장 이동·재조회·상태 전이는 native 확인 dialog를 연결한다. 작성자·현재 지정 담당자·ADMIN의 권한 차이와 DRAFT 가시성·상태 전이·history 원자성은 서버 Service에서 검사한다.

007은 일반 요구사항·담당자·검토·댓글·이력의 파일럿이다. 이미지/주석/첨부·canvas·칸반/공지/관리 UI는 010의 실제 구현 대상으로 남긴다. placeholder null/빈 관계와 범위 안내를 해당 업무 완료로 표시하지 않는다. 007의 단순 ID/username 조회·CRUD와 페이지 가시성은 JPA이며 MyBatis/Querydsl·복잡 보고/성능은 008/009에서 같은 DataSource/트랜잭션·기존 외부 계약과 함께 확대한다.

## @sc/date의 중립 날짜 계약

[date package](../../frontend/packages/date/package.json)의 직접 선택은 Day.js 1.11.23이다. [src/index.ts](../../frontend/packages/date/src/index.ts)는 vendor 객체·Vue·업무 Entity를 노출하지 않는 `@sc/date` 진입점이다. 현재 작성한 단위와 Story/두 앱의 실제 사용을 root 전체 검증에서 확인한다. 실제 경계 probe에서 확인한 vendor의 0..99년·역사적 초 단위 offset 문제는 wrapper의 calendarAnchor/Intl 경계 처리로 보강했으며 [경계 기록](../검증/007-date-year-boundary-probe.log)을 보존한다.

| 공개 API                                                               | 의미                                                                                                    |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `isCalendarDate(string)`                                               | YYYY-MM-DD의 실제 그레고리력/윤년 검사. calendar date를 Instant/시간대 변환으로 취급하지 않음           |
| `parseUtcTimestamp(string\|null)`                                      | empty/invalid/valid 구분. ISO UTC `Z`와 1~9자리 소수초의 raw를 보존하고 표시용 epochMilliseconds를 제공 |
| `createDateFormatter({locale,timeZone,emptyDisplay?,invalidDisplay?})` | 독립 ko/en·유효한 IANA time zone/UTC. 잘못된 zone을 임의 지역으로 대체하지 않음                         |
| `formatCalendarDate` / `formatTimestamp`                               | calendar 날짜는 이동하지 않고 timestamp만 지정 zone으로 표시. 원본을 저장용 문자열로 재직렬화하지 않음  |

Reference 업무 시각은 원문 UTC를 유지하고 한국어/영어·Asia/Seoul 등의 표시에만 formatter를 사용한다. 서버/H2 저장은 `TIMESTAMP(6) WITH TIME ZONE`·Clock UTC·마이크로초 정밀도다. 프런트의 raw 9자리 보존과 DB 저장 정밀도를 같은 보장으로 설명하지 않는다. Starter [DatePatterns.vue](../../frontend/apps/starter-app/src/features/patterns/DatePatterns.vue)와 Catalog의 독립 합성 예제가 locale/zone/유효성·원문 보존을 소비하며 다른 앱 feature를 import하지 않는다.

## 보안 감사와 ADMIN 조회

업무 history snapshot과 보안 감사는 다른 책임이다. core [audit](../../backend/framework-core/src/main/java/dev/scframework/core/audit)는 Spring/JPA/앱 의존성이 없는 immutable event·publisher·sink SPI다. 이벤트는 actorSubject/optional actorId·UTC occurredAt·action·SUCCESS/FAILURE/DENIED·resourceType/optional resourceId·optional requestId/reasonCode만 받는다. 길이·safe code/ID·outcome allowlist를 검사하고 본문/password/token/cookie/session/SQL/예외 message 필드를 제공하지 않는다.

[ScAuditAutoConfiguration](../../backend/framework-autoconfigure/src/main/java/dev/scframework/autoconfigure/ScAuditAutoConfiguration.java)은 `sc.framework.audit.enabled` 명시 활성과 소비 sink/publisher/Clock를 존중한다. disabled 최소 앱은 저장소가 필요 없고 enabled인데 sink/TM/schema가 없으면 조용히 저장 성공을 가장하지 않는다. Reference는 기본 활성, Starter는 기본 비활성이다. 같은 앱 H2 DataSource의 바인딩 JDBC adapter를 쓰며 라이브러리가 DDL을 생성하거나 drop하지 않는다.

| 위치                   | 수집·원자성                                                                                                                                         |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 기존 Security handlers | 로그인204·실패401·logout204·CSRF403·인증401/권한403 결과를 보존하며 한번만 수집. unknown failed username은 bounded subject/nullable ID로 허용       |
| 공통 Advice            | 업무400/403/409/500·형식/metadata 오류를 기존 code/message/errors[] 안전 JSON으로 변환하고 제한된 reasonCode만 기록                                 |
| 업무 성공 publisher    | 외부 Service transaction 완료 뒤 실제 commit인 경우만 SUCCESS를 REQUIRES_NEW에 기록. rollback된 SUCCESS는 저장하지 않음                             |
| FAILURE/DENIED         | transaction이 있으면 완료 뒤, 없으면 바로 별도 새 transaction에 기록. 주 history rollback의 원자성을 약화하지 않음                                  |
| sink 저장 실패         | 이미 커밋한 업무/HTTP를500처럼 바꾸지 않고 `failedWrites` counter와 고정 `AUDIT_SINK_FAILURE` warning을 남김. 원문/stack/SQL을 로그에 복사하지 않음 |

Reference [V3](../../backend/reference-app/src/main/resources/db/migration/V3__security_audit.sql)는 `security_audit_event`와 latest/filter index·값 제약을 소유한다. unknown login/거절/삭제 이후 식별자 보존을 위해 사용자/요구사항 FK는 없다. Starter는 자체 [application-audit.yml](../../backend/starter-app/src/main/resources/application-audit.yml) profile과 [별도 V1 migration](../../backend/starter-app/src/main/resources/db/audit-migration/V1__security_audit.sql)으로 공통 adapter를 소비하고 Reference 테이블/class를 import하지 않는다. run.sh의 Starter 전용 audit/dev,audit/prod,audit 안전 allowlist와 실제 런처8개 검사 그룹·9개 감사 이벤트 재기동 보존을 확인했다.

신규 [AuditController](../../backend/reference-app/src/main/java/dev/scframework/reference/audit/AuditController.java)의 `GET /api/audit/events`는 현재 DB ADMIN만 조회한다. `{items,total,page,size}`와 제한된 event DTO를 반환한다. page0..1,000,000·size1..100·기본20, action/outcome/actorSubject/from/to 필터는 바인딩하고 최신 occurredAt/id순으로 정렬한다. 이 경로는 원본 업무 이식 경로가 아닌 신규 운영 확장이다. 보존/삭제·durable delivery/outbox·MQ/관측·실제 운영 정책은 012에서 검증한다.

## 초기 실행 결과와 후속 검증
