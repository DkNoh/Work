# 010 보드·이미지 공통 UI 계약

`ScSortableBoard`와 `ScImageAnnotator`는 업무 자료를 받는 Vue SFC다. 보드는 이동 의도, 이미지는 원본 이미지 기준 박스 변경을 전달한다. API·세션·권한·상태 enum·revision·저장·409 처리와 이미지 파일 조회는 소비 앱이 소유한다. **010 최종 통합 빌드, 단위 139개·서버 143개, 새 JAR E2E 74개, Story 95개, 정적 Docs 22개/Controls 10개, 별도 시각 비교 4개 통과를 확인**했다. E2E 74개에는 칸반·media·Starter 보드/이미지 17개가 포함되며, 이미지 drag/resize 중 Escape 복구도 실제로 검사했다. [최종 요약](../검증/010-final-summary.json)에 실행 범위와 수동 접근성 한계를 기록했다. 외부 패키지 설치·배포 검증은 011의 별도 범위다.

## ScSortableBoard

원본은 [board/contracts.ts](../../frontend/packages/ui/src/board/contracts.ts)와 [ScSortableBoard.vue](../../frontend/packages/ui/src/board/ScSortableBoard.vue)다. `T`는 소비 앱이 정의한다. 열·항목 배열·item의 업무 값을 공통 UI에서 변경하지 않는다.

| prop            | 타입                          | 필수·실효 기본값               | 의미                                                                                                      |
| --------------- | ----------------------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------- |
| `label`         | `string`                      | 필수                           | 바깥 section의 접근성 이름과 스크롤 영역 이름의 기준                                                      |
| `columns`       | `readonly ScBoardColumn<T>[]` | 필수                           | 읽기 전용 열 목록. 각 열은 `readonly id`, `label`, `items:readonly T[]`를 가진다.                         |
| `getItemKey`    | `(item:T) => string`          | 필수                           | 모든 열을 통틀어 고유하며 비어 있지 않은 안정 키                                                          |
| `getItemLabel`  | `(item:T) => string`          | 필수                           | 이동 버튼·live 안내·기본 카드 본문의 이름                                                                 |
| `isItemMovable` | `(item:T) => boolean`         | 선택, 미지정 시 모든 항목 허용 | 항목별 이동 가능 여부. 업무 권한은 앱에서 계산한다.                                                       |
| `disabled`      | `boolean`                     | 선택, `false`                  | 보드 이동 차단. native 이동 대체 버튼을 감추고 handle을 disabled로 표시한다.                              |
| `loading`       | `boolean`                     | 선택, `false`                  | 불러오는 중 안내와 이동 차단. 기존 열·카드는 유지한다.                                                    |
| `error`         | `string`                      | 선택, 미지정                   | 비어 있지 않으면 alert와 retry 버튼을 표시한다. 자체적으로 배열을 초기화하거나 이동 권한을 바꾸지 않는다. |
| `labels`        | `Partial<ScBoardLabels>`      | 선택, 한국어 문구와 부분 병합  | 언어는 앱이 선택한다. 공통 UI가 i18n 인스턴스를 만들지 않는다.                                            |

선택 prop에는 `withDefaults` 선언이 없다. 위의 boolean은 Vue의 boolean prop 처리에 따른 `false`이고, callback·string·labels의 미지정 값은 `undefined`다. labels의 한국어 문구는 내부 표시 fallback이다. 명시적인 `{}` 기본 prop을 선언했다는 뜻이 아니다.

`ScBoardLabels`는 `loading/empty/retry/move/up/down/destination/scroll/instructions/started/cancelled/requested`를 가진다. 기본 문구는 각각 `불러오는 중`·`항목이 없습니다.`·`다시 시도`·`이동`·`위로`·`아래로`·`목적 열`·`보드 스크롤 영역`, 키보드/대체 버튼 사용 안내, `이동 시작`·`이동 취소`·`이동 요청`이다. 앱은 영어 등 필요한 문구만 재정의한다.

| 이벤트·slot | payload                                         | 계약                                                                                                                  |
| ----------- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `move`      | `ScBoardMove`                                   | `{itemKey, fromColumnId, toColumnId, beforeKey}`. 목적 열에서 `beforeKey` 항목 바로 앞에 삽입하며 `null`은 열 끝이다. |
| `retry`     | 없음                                            | 앱이 재조회한다. UI에서 HTTP를 호출하거나 오류를 자동 삭제하지 않는다.                                                |
| `item` slot | `{item:T,column:ScBoardColumn<T>,index:number}` | 카드 본문. 미지정 시 `getItemLabel(item)` paragraph를 표시한다. 링크·업무 버튼의 권한과 동작은 앱이 연결한다.         |

열 ID와 전체 item key의 중복·빈 값은 `TypeError`로 거절한다. 잘못된 자료를 내부 임의 ID로 치환하지 않는다. 자기 자신을 `beforeKey`로 지정하거나 위치가 그대로인 이동, 존재하지 않는 열·대상 key의 이동은 emit하지 않는다. 같은 열의 아래쪽 카드에 drop하면 그 카드 뒤에 놓는 의도로 변환한다. API의 `beforeId`·revision으로 바꾸는 것은 앱의 책임이다.

### 입력·순서·focus

- `DragDropProvider`의 pointer/keyboard 센서와 SortableKeyboardPlugin을 사용한다. handle에서 Space/Enter로 시작·완료하고 방향키로 이동하며 Escape는 취소한다. 이동 종료는 서버 저장 완료를 뜻하지 않는다.
- `OptimisticSortingPlugin`을 제외하여 서버 승인 전에 입력 배열이나 DOM 순서를 바꾸지 않는다. 부모가 성공 응답으로 `columns`를 교체하거나 앱이 소유한 항목 배열을 갱신할 때 순서가 반영된다. 실패·403·409이면 앱이 기존 자료와 입력을 유지하고 오류를 공급한다.
- 항목의 native 위로/아래로 버튼은 같은 열 이동, 목적 열 select와 이동 버튼은 다른 열의 끝으로 이동한다. 같은 목적 열 선택·처음 항목 위로·마지막 항목 아래로는 disabled다. 모든 수단이 동일한 `move`를 전달한다.
- 보드 바깥 section 안에 별도 이름을 가진 `tabindex="0"` 스크롤 region이 있고 각 열은 이름 있는 section·h2·ul, 카드는 li다. 좁은 화면의 가로 overflow는 내부 region이 맡는다. pointer 조작을 하지 않는 사용자는 native 이동 수단을 이용할 수 있다.
- 이동 요청의 caller가 보드 내부에 있을 때 항목 key·원래/목적 열·beforeKey·caller를 기록한다. 열 ID와 항목 key 순서를 감시하므로 부모가 같은 `items` 배열을 `splice`해도 이동을 감지한다. 실제 목적 열과 삽입 위치가 반영된 뒤 같은 열의 연결된 유효 caller는 유지하고, 교차 열 이동이나 caller 제거/비활성화로 focus가 body에 돌아간 경우 같은 key의 비활성화되지 않은 handle로 복구한다. 사용자가 다른 요소로 옮긴 focus는 빼앗지 않는다. 지연 Query·이동 없는 실패를 성공으로 추측하지 않으며 이전 비동기 watcher가 새 pending 요청을 지우지 못하도록 구분한다. aria-hidden drag clone은 복구 대상에서 제외한다.
- 라이브 안내는 polite status와 dnd-kit 접근성 plugin을 사용한다. `useId()` 기반 prefix로 안내·열 heading·목적 열 label ID를 구분한다. 직접 전달한 DOM ID의 고유성은 앱이 보장한다.

**일반 readonly prop은 없다.** 전체 읽기 전용은 `disabled`, 항목별 읽기 전용은 `isItemMovable`로 표현한다. 카드 slot의 링크는 사용할 수 있으며 slot의 임의 업무 버튼까지 공통 UI가 disabled로 바꾸지 않는다. `disabled`/`loading`은 바깥 `aria-busy`에도 반영된다. 이 표시가 서버 권한 검사를 대체하지 않는다.

provider가 소유하는 manager는 unmount에서 destroy하고 sortable/droppable 등록과 monitor listener는 라이브러리 watcher 수명에 따라 해제한다. 공통 UI가 별도의 전역 drag listener·HTTP·타이머를 등록하지 않는다. plugin 옵션의 함수값은 `computed`로 전달한다. 설치된 Vue adapter의 `toValue`가 이를 getter로 조기 호출하지 않도록 한 내부 호환 처리이며 public prop에 plugin 옵션을 추가하지 않는다.

### 중립 사용 예

```vue
<template>
  <sc-sortable-board
    label="준비와 완료"
    :columns="columns"
    :get-item-key="itemKey"
    :get-item-label="itemLabel"
    @move="applyLocalMove"
  >
    <template #item="{ item }">
      <p>{{ item.title }}</p>
    </template>
  </sc-sortable-board>
</template>
<script setup lang="ts">
import { ref } from "vue";
import { ScSortableBoard, type ScBoardColumn, type ScBoardMove } from "@sc/ui/board";

interface Item {
  id: string;
  title: string;
}
const columns = ref<readonly ScBoardColumn<Item>[]>([
  { id: "ready", label: "준비", items: [{ id: "a", title: "첫 항목" }] },
  { id: "done", label: "완료", items: [] },
]);
const itemKey = (item: Item) => item.id;
const itemLabel = (item: Item) => item.title;
function applyLocalMove(move: ScBoardMove) {
  const item = columns.value
    .find((column) => column.id === move.fromColumnId)
    ?.items.find((candidate) => candidate.id === move.itemKey);
  if (!item) return;
  columns.value = columns.value.map((column) => {
    const items = column.items.filter((candidate) => candidate.id !== move.itemKey);
    if (column.id === move.toColumnId) {
      const index =
        move.beforeKey === null
          ? items.length
          : items.findIndex((candidate) => candidate.id === move.beforeKey);
      items.splice(index < 0 ? items.length : index, 0, item);
    }
    return { ...column, items };
  });
}
</script>
```

이 예는 서버가 없는 중립 로컬 보드다. 업무 화면은 `applyLocalMove` 대신 앱의 command를 호출하고 성공 후 Query를 갱신한다. 필터로 일부 자료만 조회한 보드에서 전체 순서를 추측해 저장하지 않는다.

## ScImageAnnotator

원본은 [image/contracts.ts](../../frontend/packages/ui/src/image/contracts.ts), [ScImageAnnotator.vue](../../frontend/packages/ui/src/image/ScImageAnnotator.vue), [좌표 검사](../../frontend/packages/ui/src/image/coordinates.ts)다. box와 annotation은 읽기 전용이며 공통 UI는 저장 가능한 **박스 하나**를 model로 다룬다. 기존 annotation 목록은 별도의 선택 대상이다.

| prop                   | 타입                           | 필수·실효 기본값              | 의미                                                                                             |
| ---------------------- | ------------------------------ | ----------------------------- | ------------------------------------------------------------------------------------------------ |
| `image`                | `HTMLImageElement \| null`     | 필수                          | 앱이 decode를 마친 이미지. `null`은 이미지 없음이다.                                             |
| `imageDescription`     | `string`                       | 필수                          | 눈에 보이는 figcaption, 스크롤 region과 canvas wrapper의 접근성 이름                             |

| `annotations`          | `readonly ScImageAnnotation[]` | 선택, 미지정 시 빈 목록       | 기존 박스. 각 항목은 고유 비어 있지 않은 `id/label`과 유효한 `box`다.                            |

| `loading`              | `boolean`                      | 선택, `false`                 | status를 표시하고 편집·zoom·annotation 선택을 차단한다. 기존 이미지가 있으면 canvas를 유지한다.  |
| `error`                | `string`                       | 선택, 미지정                  | alert·retry 표시. image/model을 초기화하거나 편집 가능 상태를 자동 변경하지 않는다.              |
| `labels`               | `Partial<ScImageLabels>`       | 선택, 한국어 문구와 부분 병합 | 앱의 locale에 맞는 문구를 전달한다.                                                              |

선택 prop의 기본값 선언과 boolean 처리 구분은 보드와 같다. `ScImageLabels`의 키는 `loading/noImage/retry/coordinates/x/y/width/height/apply/clear/zoom/instructions/invalid/changed/cancelled/annotations`다. 기본 문구는 `불러오는 중`·`이미지가 없습니다.`·`다시 시도`·`주석 좌표`·`가로 시작`·`세로 시작`·`너비`·`높이`·`좌표 적용`·`박스 지우기`·`확대`, 이미지 드래그/좌표 입력/Escape 안내, 좌표 오류 안내, `박스 변경`·`그리기 취소`·`기존 주석`이다.

| 이벤트              | payload                   | 계약                                                                                                                              |
| ------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `update:modelValue` | `ScNormalizedBox \| null` | 완성한 유효 박스 또는 지우기 `null`. 앱이 받아 model을 갱신한다. pointermove 중 임시 preview는 저장 이벤트가 아니다.              |
| `select-annotation` | `string`                  | 기존 annotation ID 선택. 선택 상태·상세 URL·권한은 앱이 처리한다. readonly에서도 전달하며 disabled/loading에서는 전달하지 않는다. |
| `retry`             | 없음                      | 앱의 이미지 조회·decode 재시도. disabled이면 버튼은 disabled다.                                                                   |

공개 slot은 없다. native 번호 입력/figure·Konva stage/layer/node·Transformer를 임의 slot이나 options로 교체하지 않는다. 불필요한 외부 handler/Vuetify prop 전달도 공개 API가 아니다.

### 좌표·pointer·키보드 대체 수단

`ScNormalizedBox`는 `readonly {x,y,width,height}`다. 모두 유한한 number이고 `x/y >= 0`, `width/height > 0`, `x+width <= 1`, `y+height <= 1`이어야 한다. `isNormalizedBox(unknown)`은 이 조건을 검사하는 공개 type guard다. pixel·CSS 좌표·Date·문자열·NaN·Infinity·크기 0은 유효 박스가 아니다. 잘못된 model/annotation props는 `TypeError`로 거절한다.

- Stage/Image 배경의 pointerdown→move→up으로 양방향 드래그 박스를 만든다. 완료 전에 중간 preview를 쓰며 zero-area는 emit하지 않는다. 기존 박스와 Transformer 위 동작은 새 그리기와 구분한다.
- 현재 박스는 draggable이고 Transformer는 네 모서리 resize를 제공한다. 회전·flip은 제공하지 않는다. 변환 scale을 실제 width/height로 합친 뒤 scale을 1로 되돌리고 유효한 normalized box를 emit한다. 이미지 밖으로 이동한 박스는 경계 안으로 제한한다.
- 확대는 내부 UI 상태다. `1×`부터 `3×`, step `0.25`의 native range를 사용하며 좌표 model은 확대해도 원본 기준이다. canvas 표시 폭은 host 폭·naturalWidth와 확대를 기준으로 계산하고 원본 종횡비를 유지한다. 내부 overflow region의 최대 표시 높이는 `640px`이다.
- native 숫자 입력 4개와 좌표 적용/지우기 버튼으로 canvas 없이도 박스를 편집할 수 있다. 입력 중 문자열은 로컬 draft이고 적용 시에만 검사·emit한다. 잘못된 입력은 alert 및 필드 `aria-invalid/describedby`로 알리며 마지막 model을 보존한다.
- 기존 annotation은 canvas click/tap과 이름 있는 native 버튼 양쪽에서 선택할 수 있다. 좌표도 목록에 텍스트로 표시한다. canvas 하나에 모든 접근성 책임을 맡기지 않는다.
- Escape는 그리기 preview와 진행 중 drag/resize를 취소한다. drag/resize 시작 box를 보관했다가 노드 위치·크기·scale을 복구하며 취소를 저장 이벤트로 전달하지 않는다. readonly/disabled/loading 전환으로 편집 불가가 되면 진행 중 입력을 취소한다.

부모의 새 `modelValue`는 native 좌표 draft에 반영한다. 새 `image`는 진행 중 gesture를 취소하고 zoom을 1로 되돌리지만 model을 임의로 지우지 않는다. 이미지 버전 선택 변경의 박스 초기화·미저장 확인은 앱이 소유한다. 공통 model 연결을 사용한 상태에서 외부 응답이 draft를 덮어쓰지 않도록, 앱은 상세 초기화 시점을 선택 전환·명시 reload·저장 성공으로 제한한다.

host ResizeObserver는 unmount에서 disconnect한다. 실제 브라우저 pointer capture는 완료/취소/unmount에서 release하며 synthetic pointer에는 capture를 요구하지 않는다. Transformer 연결도 unmount에서 해제한다. Stage/Layer/Shape의 해제는 vue-konva 컴포넌트 수명에 따른다. HTTP AbortController·Blob ObjectURL·decode 응답의 선택 epoch는 공통 UI가 아닌 소비 앱의 파일 composable 책임이다.

### 중립 사용 예

```vue
<template>
  <sc-image-annotator
    v-model="box"
    :image="image"
    image-description="선택한 원본 이미지"
    :annotations="annotations"
    :selected-annotation-id="selectedId"
    @select-annotation="selectedId = $event"
  />

defineProps<{ image: HTMLImageElement | null }>();
const box = ref<ScNormalizedBox | null>(null);
const selectedId = ref<string | null>(null);

  { id: "sample", label: "기존 영역", box: { x: 0.1, y: 0.2, width: 0.3, height: 0.4 } },

</script>
```

`image=null`은 안내와 disabled 좌표 입력을 표시한다. `loading=true`는 별도 status, `error`는 alert/retry를 표시한다. 자동 HTTP 재시도는 하지 않는다. error를 표시해도 현재 image/model을 유지할 수 있으므로 접근 권한 상실 등 편집 금지가 필요하면 앱이 disabled/readonly도 전달한다.

보드의 `PointerSimulationAndNativeMove`는 `isPrimary=true/isTrusted=false`인 **합성 DOM PointerEvent**와 animation frame 간격을 사용한다. 실제 sensor의 dragging 표시 → 둘째 열 이동 → exact move payload → native 목적 열/버튼으로 첫 열 복귀 및 순서를 검사한다. capture가 항상 실패하거나 합성 입력이 항상 취소된다고 단정하지 않는다. `KeyboardSensorCancel`은 Escape 후 정확한 빈 출력과 focus를 검사하고, native 이동+409 유지·읽기 전용·loading Story도 포함한다. 이는 trusted pointer 입력을 대신하는 증거가 아니다.

이미지 Story는 좌표 오류+기존 주석 선택·합성 pointer draw·readonly·Konva move/Transformer resize·empty·loading·error/retry를 다룬다. `MoveResizeAndZoom`의 range 변경은 합성 `input` 이벤트 시뮬레이션이며 native ArrowRight 기본 동작을 검사했다고 기록하지 않는다. canvas에 보내는 합성 입력의 결과는 실제 normalized model과 canvas 표시로 확인한다.

별도 JAR의 칸반 E2E는 Playwright의 trusted mouse/keyboard 센서·Escape·native 이동·필터 이동 차단과 API 상태 저장을 검사했다. 이미지 E2E는 native range의 **ArrowRight/Home**, 확대 후 box 불변, trusted pointer 그리기·박스 이동·Transformer resize, 그리기 도중 Escape 후 이전 box 보존을 검사했다. API 저장·본문 변경 시 버전/box 보존·409 입력 보존·PDF 다운로드/타인 차단·EXIF6·ADO export도 같은 새 JAR에서 확인했다. 접근성 규칙 제외·CSS 강제 변경·force 클릭으로 실패를 통과시키지 않았다.

추가한 drag/resize 취소 검증은 좌표 값만 비교하지 않는다. 성공한 기존 이동·resize 뒤 시작 canvas의 `toDataURL` SHA-256을 읽고, 실제 mouse gesture의 중간 canvas가 달라진 것을 확인한다. 두 animation frame 뒤 Escape를 보내 다시 두 frame을 기다린 다음 시작 canvas와 normalized 좌표로 복구되며 mouseup 후에도 유지되는지 검사했다. **390px drag·resize와 1366px drag·resize 총 4개 assertion이 실제로 통과**했다. 제품 debug hook·Konva 내부 node 조회·직접 emit을 사용하지 않았다. 코드의 `info.attach({body})`는 사용한 list reporter에서 별도 JSON 파일로 저장되지 않았으므로, 취소 전/중/후 hash JSON 파일을 보존했다고 주장하지 않는다. 실제 assertion·E2E source·통과 로그·최종 요약이 증거다.

Starter 신규 2개도 합성 로컬 예제 자료를 실제로 조작하여 통과했다. 보드는 위/아래 native 버튼과 목적 열 선택·이동·focus를, 이미지는 영어 좌표 적용·오류 시 이전 model 유지·native range ArrowRight/Home·주석 버튼 선택을 검사했다. 전체 document의 axe와 페이지 overflow, 초기화 및 조작 중 업무 API 요청 없음도 확인했다.

실제 통과 수와 초기 실패는 위 로그와 [최종 요약](../검증/010-final-summary.json)에 한정해 기록했다. axe의 incomplete 수동 판별, VoiceOver/스크린리더 실제 낭독, 모든 키보드 동선·해상도·이미지 포맷의 수동 확인과 외부 CI 실행은 완료로 주장하지 않는다. 010의 로컬 통합 통과와 011의 외부 패키지 배포·격리 설치는 별도 검증이다.
