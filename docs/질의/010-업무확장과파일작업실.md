## 업무·상태·서버 계약

모든 HTTP는 현재 DB actor로 접근·수정 권한을 판단한다. 칸반 회원 철회는 다음 요청에 반영되고 ADMIN도 타인이 작성한 작업·공지의 변경 권한을 갖지 않는다. 작업 이동은 같은 보드·유한 position·현재 revision CAS를 검사한다. 실패와 409에서 입력을 보존하고 저장 결과를 기능별 Query에 반영한다. 포인터·키보드 sensor와 별도로 일반 이동 조작을 제공하며 필터 정렬에서는 보드 직접 이동을 제한한다. 실제 공유 세션은 Pinia, URL은 Router, 서버 자료는 Query, 저장 전 입력은 해당 폼이 원본이다.

날짜는 달력 `YYYY-MM-DD`와 UTC 시각을 구분하며 한영 표시가 원문을 바꾸지 않는다. `POST /api/kanban/tasks/import`는 최대 200행을 먼저 모두 검증하고 하나의 transaction에서 저장한다. 잘못된 달력 날짜·태그·권한 오류는 원래 XLSX 물리 행에 연결하며 부분 저장하지 않는다. 확인한 staging만 명시적으로 저장하고 자동 재시도하지 않는다. [API](../api.md)와 [유지보수 위치](../maintenance-guide.md)에서 입력·다운로드·재전송 정책을 함께 확인한다.

이미지 버전은 생성 후 불변이며 요구사항과 원본 버전·박스 하나를 연결한다. 보관 버전의 기존 요구사항·파일·박스는 조회/편집할 수 있고 새로운 요구사항 연결은 거절한다. 요청 revision을 확보한 뒤 자식을 변경하며 버전/박스 번호는 부모 잠금과 단조 counter로 할당한다. 삭제한 박스 번호를 재사용하지 않는다. 박스는 유한한 원본 0~1 좌표·양의 크기·이미지 경계를 검사한다. 작성자만 요구사항 박스·첨부를 변경하고 ADO metadata는 AGREED/ADO_LINKED에서 작성자 또는 지정 검토자만 기록한다. ADMIN override·외부 ADO 계정/API 호출은 없다.

파일은 10 MiB, opaque UUID/root 경계·일반 파일/NOFOLLOW·실제 PNG/JPEG decode·PDF signature와 private DRAFT 읽기 권한을 검사한다. 원본 bytes는 재압축하지 않는다. DB rollback에서는 새 파일을 정리하고 첨부 삭제는 metadata commit 뒤 실제 파일을 정리한다. 이미 commit된 HTTP를 cleanup I/O 오류로 500으로 바꾸지 않고 bounded 운영 신호를 남긴다. 성공한 write 뒤 입력 stream close가 실패해도 blob/Starter whitelist를 정리하는 실제 테스트가 통과했다. PDF signature 검사는 악성 콘텐츠 검사나 전체 PDF 의미 검증을 대신하지 않는다.

JPEG 좌표 축은 원본 bytes의 EXIF orientation을 적용한 표시 기준이다. 5~8에서는 공개 width/height를 교환하고 브라우저에서 decode한 natural dimensions와 맞춘다. 제한된 TIFF endian/offset/type/count/orientation 파서를 사용한다. PNG eXIf는 기본 방향 1만 지원하고 회전·반전 PNG는 안전 400으로 거절한다. 서버 EXIF/업로드와 실제 작업실 브라우저 검증은 통과했다. 전체 vendor metadata 지원을 주장하지 않는다. [HTML 이미지 크기 명세](https://html.spec.whatwg.org/multipage/embedded-content.html#dom-img-naturalwidth), [JDK 21 JPEG metadata 명세](https://docs.oracle.com/en/java/javase/21/docs/api/java.desktop/javax/imageio/metadata/doc-files/jpeg_metadata.html).

서식 문서는 허용 node/mark/링크, depth 32/node 10,000/텍스트 UTF-16 1,000,000을 서버에서도 검사한다. 임의 HTML 저장/렌더로 우회하지 않는다. 공통 UI·Java가 공유한 링크 56개 golden vector는 지원 protocol/형식의 일치를 검증하며 WHATWG URL 전체 표준과 Java 파서의 동등성을 뜻하지 않는다. 기존 plain text API는 서식 JSON으로 바꾸지 않는다.

Flyway V1~V3 원문/checksum은 보존했다. V4는 미디어·파일과 V2의 `screen_version_id IS NULL` CHECK 제거·실제 FK, V5는 칸반·공지·독립 문서다. fresh H2와 V1~V3 upgrade, 기존 UTC·업무 행 보존을 실제 확인했다. 공통 라이브러리는 업무 DDL을 자동 생성하지 않는다. 단순 조회/쓰기 JPA와 현재 Querydsl 동적 목록·MyBatis 복잡 보고서 경계도 유지한다.
