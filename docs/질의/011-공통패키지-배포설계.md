# 011 프런트 공통 패키지 배포 설계

2026-10-07의 읽기 전용 준비안을 바탕으로 실제 구현한 프런트 생산 계약이다. 상위 범위는 [011 진행 검토](011-배포와생성기-준비검토.md)다. 최초 다섯 패키지 `0.1.0`의 생산·pack과 외부 타입 소비를 실제 확인했다. 현재 public 버전은 `0.2.0`, 공통 backend는 `0.2.0-SNAPSHOT`이며 API·DDL과 생성 앱 자체 버전은 유지한다. [cohort 변경 증거](../검증/011-version-cohort.json)를 연결한다. **최종 새 브라우저·upgrade/rollback·011 전체 완료는 아직 선언하지 않는다.** 이전 후보·해시·초기 실패를 덮어쓰지 않고 새 세트를 검사한다.

## 실제 배포 단위와 생산 구현

| 패키지        | 실행·타입 산출물                                                       | 외부 사용 환경·보존 계약                                                                                          |
| ------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `@sc/ui`      | Vite 다중 ESM entry + vue-tsc 선언 + 단일 CSS + 생성 Sass tokens       | Vue CSR/bundler. 기본 진입점과 table/charts/editor/board/image를 분리하고 22개 자체 UI 계약 유지                  |
| `@sc/runtime` | Vite 단일 ESM entry + TypeScript 선언 + 중립 `generated/api.d.ts` 복사 | Vue/Router/Pinia/Query와 단일 runtime. 기본 Identity와 앱-owned decoder·JSON/Blob/ArrayBuffer·세션/CSRF 계약 유지 |
| `@sc/date`    | 단일 ESM entry + TypeScript 선언                                       | Node/브라우저의 UTC·달력·locale·IANA 표시. 원본 UTC 소수초 및 0000/0099 보존                                      |
| `@sc/excel`   | 단일 ESM entry + TypeScript 선언                                       | Node와 브라우저의 XLSX bytes adapter. Date/문자열·formula 제한·원본 `sourceRowNumbers` 유지                       |
| `@sc/i18n`    | 단일 ESM entry + TypeScript 선언                                       | 소비 Vue 앱의 독립 Composition I18n 인스턴스와 한국어 fallback/앱 메시지 병합                                     |

각 package의 `build`는 `scripts/build-library.mjs`를 호출한다. 공통 `library-config.mjs`가 Vite `8.3.1` library mode의 `formats:['es']`, `build.rolldownOptions.external`을 설정하고 JS를 생성한다. UI는 root와 다섯 선택 경로의 6개 JS entry·단일 CSS를, 나머지는 단일 JS entry를 생산한다. 선언은 TypeScript `5.9.3`/vue-tsc `3.3.12`가 생성한다. CJS/UMD/SSR·Node canvas 지원은 추가하지 않았다. 자체 SFC source는 template 기반이며 Vue compiler가 생성하는 실행 JS는 배포 산출물이다.

`tsc`의 JS emit만 쓰면 현재 source의 `./http` 같은 상대 import에 확장자가 남아 native ESM에서 실패할 수 있다. 이 때문에 단순 TS 패키지도 첫 구현에서는 library bundler를 사용한다. vendor는 아래 외부화 규칙으로 남기고 자체 상대 chunk는 실제 `.js` 대상으로 생성·검사한다.

## exports와 자산 배치

다음은 실제 생성된 파일과 조건부 exports다. 각 대상의 존재와 현재 source/config digest 일치를 확인했다.

| 현재 공개 경로  | 목표 exports 대상                                                                                                     |
| --------------- | --------------------------------------------------------------------------------------------------------------------- |
| 각 패키지 `.`   | `types:./dist/types/index.d.ts`, `import/default:./dist/index.js`                                                     |
| `@sc/ui/table`  | `types:./dist/types/table/index.d.ts`, `import/default:./dist/table.js`                                               |
| `@sc/ui/charts` | `types:./dist/types/charts/index.d.ts`, `import/default:./dist/charts.js`                                             |
| `@sc/ui/editor` | `types:./dist/types/editor/index.d.ts`, `import/default:./dist/editor.js`                                             |
| `@sc/ui/board`  | `types:./dist/types/board/index.d.ts`, `import/default:./dist/board.js`                                               |
| `@sc/ui/image`  | `types:./dist/types/image/index.d.ts`, `import/default:./dist/image.js`                                               |
| `@sc/ui/styles` | side-effect CSS `./dist/sc-ui.css`, side-effect import용 `types:./dist/types/styles.d.ts`                             |
| `@sc/ui/tokens` | `sass/default:./dist/tokens.scss`. JS module로 import하는 경로가 아니며 runtime `uiTokens`는 기존 UI 루트 export 유지 |

`types` 조건은 각 JS 경로에서 먼저 선언한다. export 키는 현재 이름을 유지하고 `./src/*`·`./dist/*` wildcard를 만들지 않는다. private helper 파일을 타입 의존성 해결용으로 포함하더라도 public subpath가 되는 것은 아니다. exports는 import 경계이며 tarball의 파일 내용을 숨기는 보안 장치로 해석하지 않는다.

CSS 계약은 **단일 `@sc/ui/styles`**다. UI library build의 모든 SFC CSS와 private `library/styles.ts`가 가져오는 `src/styles.scss`를 `cssCodeSplit:false`·`cssFileName:'sc-ui'`로 추출한다. table/chart/editor/board/image의 scoped CSS도 이 파일에 포함된다. 기능 JS를 나눴다고 CSS나 설치 dependency까지 선택적으로 제거된다고 주장하지 않는다. private CSS 수집용 `dist/__styles.js`는 빌드 완료 전에 제거한다.

소비 앱은 `import 'vuetify/styles'` 뒤에 `import '@sc/ui/styles'`를 한 번 실행한다. 현재 UI는 `vuetify/components`를 명시 import하고 Vuetify component JS는 자체 CSS를 import한다. 따라서 별도 소비 빌드에서 peer의 CSS도 실제 처리해야 한다. 기본 CSS 로드·component CSS·theme·focus·radius·scoped selector를 화면 computed style과 axe로 확인한다. asset 파일 존재 검사만으로 스타일 검증을 대신하지 않는다.

tokens는 `tokens.ts` → 생성 `tokens.scss`의 단일 원본을 유지한다. pack 전에 `tokens:check`를 하고 생성 Sass를 그대로 복사한다. 소비 SFC의 `@use '@sc/ui/tokens' with ($sc-emit-css:false)`로 breakpoint만 쓰는 현재 계약을 보존한다. Vite의 Sass resolver와 native Sass의 package importer는 같은 설정이 아니므로 Vite의 bare path 및 필요 시 `pkg:@sc/ui/tokens`/NodePackageImporter를 구분해 검증한다. CSS 토큰을 consumer 설치 시 다시 생성하지 않는다.

## declaration 생성과 native import 경계

각 패키지의 독립 `tsconfig.build.json`은 `noEmit:false`, `declaration:true`, `emitDeclarationOnly:true`, `rootDir:'src'`, `outDir:'dist/types'`를 지정한다. spec·Story·fixture·앱 generated schema를 제외하고 앱 paths·`vite/client`를 상속하지 않는다. Excel 생산 설정만 ExcelJS vendor 선언의 `stream`/`events`/`NodeJS` 해석을 위해 `types:['node']`를 쓴다. 자체 Excel 공개 선언과 JS에는 Node builtin·Buffer 참조가 없으며, 이것으로 브라우저 consumer에 Node ambient 설정을 요구하지 않는다.

| 실제 위험 지점                                                             | 필요한 구현·검증                                                                                                                                                                                                             |
| -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| runtime `export type {components as ApiComponents} from './generated/api'` | 기존 입력 `.d.ts`는 declaration emit만으로 복사되지 않으므로 중립 호환 `api.d.ts`를 명시 복사한다. Reference 전체 업무 API 타입으로 교체하지 않는다.                                                                         |
| UI `.vue.d.ts`와 extensionless 상대 선언 import                            | `library-artifacts.mjs`가 AST로 상대 specifier를 실제 선언 대상의 `.js` 경로로 정규화한다. `.vue.js` 참조의 선언 대상은 실제 `.vue.d.ts`이며 파일명을 임의 변경하지 않는다. 외부 Bundler/NodeNext 소비 검사는 별도 항목이다. |
| `createScI18n/createFrameworkRuntime/createScVuetify`의 inferred 반환 타입 | 실제 declaration emit의 portable type 오류를 먼저 확인한다. 오류가 있으면 공개 vendor 타입을 사용한 명시 반환 계약으로 정리하며 type assertion/any나 설치 경로로 감추지 않는다.                                              |
| 공통 UI 자체 Props/Emits/Slots                                             | vendor options·Reference DTO·업무 enum을 선언에 유입하지 않는다. theme/runtime/I18n factory의 이미 존재하는 vendor 기반 반환 타입과 구분한다.                                                                                |
| 상대 declaration reference                                                 | tarball 안의 실제 파일로 끝나는지 AST로 검사한다. `node_modules/.pnpm`, 원본 절대 경로·workspace source alias가 남지 않게 한다.                                                                                              |

새 declaration bundling 의존성은 추가하지 않았다. AST 후처리는 import/export/import-type/import-equals의 상대 specifier만 다루며 중첩 generic import-type도 변환한다. 주석·업무 문자열·vendor bare import는 전역 치환하지 않는다. 실제 대상 없는 선언 import는 빌드를 차단한다. generic SFC의 Props·Slots·row/item 타입과 `FrameworkRuntime<앱 Identity>`의 조건부 decoder 필수 타입은 실제 외부 positive/negative에서 확인했다. 생성 선언을 손으로 커밋해 오류를 우회하지 않는다.

ESM이라는 표현은 모든 경로가 bare Node import를 지원한다는 뜻이 아니다. **UI는 Vuetify CSS와 DOM/canvas를 사용하는 브라우저 bundler 패키지**다. UI 루트·CSS·Sass를 일반 Node에서 import한 결과를 SSR 지원 판정으로 삼지 않는다. date/excel/i18n/runtime의 실제 Node native ESM smoke 4개는 통과했다. runtime은 memory history의 초기 session/cache와 dispose를, Excel은 실제 bytes 왕복을 검사했다. 이것으로 SSR·외부 HTTP·전체 인증이나 모든 IANA 환경을 보장하지 않는다. 다섯 패키지와 UI 선택 subpath의 최종 production 브라우저 판정은 별도다.

## peer·외부화·라이선스

`external(id)`는 상대 경로·절대 경로·Vite virtual module을 제외한 모든 bare import를 외부화한다. 알 수 없는 bare module까지 bundle에 숨기지 않고 후속 artifact AST 검사에서 명시 dependency/peer 누락으로 차단한다. scoped package 이름은 앞 두 segment를 함께 읽는다. `vue`, `vuetify/components`, `vuetify/iconsets/mdi-svg`, `@dnd-kit/vue/sortable`, `echarts/core`, Day.js plugin/locale를 포함한 실제 bare import가 설치 manifest에서 해석되어야 한다. vendor private 파일을 새로 참조하지 않는다.

| 패키지  | 현재 peer                                                        | 현재 dependency                                                                   | 배포 확인                                                                                                                            |
| ------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| UI      | Vue `3.5.43`, Vuetify `4.2.4`                                    | TanStack Table/Virtual·Tiptap·ECharts/vue-echarts·DnD·Konva/vue-konva·Floating UI | Vue/Vuetify 외부화와 기본 entry에서 선택 vendor runtime 미유입. 한 UI manifest에 모든 dependency가 있어 기본 소비도 설치 비용을 받음 |
| runtime | Vue `3.5.43`, Router `5.3.1`, Pinia `4.0.3`, Vue Query `5.104.1` | Axios `1.20.0`                                                                    | 단일 peer module/injection과 기존 JSON/Blob/session/CSRF. 중복 runtime 자체 bundle도 별개 injection key를 만들 수 있음               |
| i18n    | Vue `3.5.43`                                                     | Vue I18n `11.1.12`, `@intlify/devtools-types 11.1.12`                             | 실제 strict 선언 생산 통과. 앱 직접 Vue I18n과 버전 동기화; 외부 설치의 module 해석/dedupe는 별도 검증                               |
| date    | 없음                                                             | Day.js `1.11.23`                                                                  | UTC/timezone plugin 및 ko/en locale import 포함. factory locale/zone 독립성과 별개로 module의 plugin 등록 side effect가 있음         |
| excel   | 없음                                                             | ExcelJS `4.4.0`                                                                   | 브라우저 resolver가 vendor `browser` entry를 사용하고 불필요한 Node builtin/native backend를 요구하지 않아야 함                      |

peer 범위는 첫 외부 consumer에서 현재 exact 버전을 유지한다. 호환 범위를 넓히는 작업은 별도 실제 matrix 결과가 있을 때 한다. peer를 bundle에 넣어 중복 Vue/Router/Pinia/Query를 만들지 않는다. vendor를 JS 외부화해도 consumer 설치 시 dependency가 없어지는 것은 아니다.

자체 패키지에 `private:true`, `license:'UNLICENSED'`, package-local `UNLICENSED`를 명시했다. public npm publish와 자체 MIT 전환은 포함하지 않는다. 직접 OSS/vendor/peer는 MIT이고 **ECharts는 Apache-2.0**다. `THIRD_PARTY_NOTICES`는 package-local 실제 설치 버전을 검사하고 직접 runtime dependency/peer의 LICENSE/COPYING/NOTICE 원문을 보존한다. import-only vendor를 실행하거나 private package.json을 import하지 않는다. 파일명이 LICENSE인 디렉터리만 있으면 성공으로 처리하지 않는다. 이는 전체 transitive npm 라이선스 inventory를 완료했다는 주장이 아니며 원래 vendor·transitive 고지는 각각 적용된다. Apache/MIT 원문을 자체 코드의 라이선스로 바꾸지 않는다.

UI의 Floating UI manifest pin은 `1.7.6`이며 UI-local node_modules/lock도 `1.7.6`이다. 루트에는 다른 transitive `1.8.0`이 함께 있어 루트 node_modules만 읽으면 직접 설치 버전을 잘못 기록할 수 있다. inventory는 각 package의 실제 resolve/lock 경로를 사용한다.

ExcelJS가 요구하는 `uuid:^8.3.0`에 대한 현재 루트 override `11.1.1`은 **tarball을 소비하는 다른 프로젝트에 전파되지 않는다.** consumer/generator의 루트 manifest에 검증된 override 정책을 제공하고 actual npm audit·XLSX 왕복을 재검증한다. 라이브러리 package 안의 overrides만으로 nested consumer 설치를 통제하지 않는다. 원본 레포의 audit 0을 외부 consumer의 결과로 재사용하지 않는다.

Konva의 canvas/skia backend는 서버/native 선택 경로다. 브라우저 ImageAnnotator 소비 때문에 native backend를 설치하지 않는다. ExcelJS/Axios의 Node 전용 경로는 Node smoke에서 허용하고 브라우저 bundle에서 unresolved builtin·네트워크·native import 오류가 없는지 확인한다. 모든 패키지에 `sideEffects:false`를 일괄 지정하지 않는다. UI CSS/SCSS와 Day.js plugin/locale 효과를 보존하고 production tree shaking으로 실제 동작을 확인한다.

## 필요한 코드·테스트 목록과 실행 순서

생산 구현과 외부 전달 검증의 상태를 구분한다. 첫 `0.1.0` 산출물을 보존한 뒤 버전 업그레이드·되돌리기를 별도로 검증한다.

| ---- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 1    | 각 package library config/`tsconfig.build.json`, 공통 build/선언 helper | 실제 5개 생산 build exit0, helper 4개 테스트 PASS; 전체 workspace 회귀는 루트 통합 판정                            |
| 2    | exports/types/files/license/sideEffects/README·NOTICE·tokens 복사       | 실제 대상 존재·stamp/digest 일치·단일 CSS·Sass 복사 확인; tar forbidden file 검사는 별도                           |

`frontend/packages/ui/source-entries.json`은 `{format:1,entries:{...}}`로 root/styles/tokens/table/charts/editor/board/image의 실제 source 경로를 지정한다. 공개 exports의 8개 키와 일치하는 입력으로 source 계약 도구가 22개 UI를 읽고 build가 `dist/CONTRACTS.json`에 format2 metadata를 복사한다. runtime exports에 `src` 조건을 넣지 않는다. source AST와 소비 artifact 계약을 둘 다 유지하며 0개 집계를 성공으로 처리하지 않는다.

`files` allowlist는 정확히 `dist`, `README.md`, `UNLICENSED`, `THIRD_PARTY_NOTICES`다. source registry·tests·stories·fixture·원본 source·Reference DTO·업무 OpenAPI snapshot·DB·업로드·secret·`.runtime`·JAR는 대상이 아니다. source/declaration map도 생성하지 않는다. 소비자의 install/prepare에서 source 빌드를 실행해 미완성 tarball을 복구하지 않는다.

생산이 모두 끝나야 `dist/build-manifest.json`의 `{format:1,name,version,inputsDigest}`를 생성한다. digest는 생산 source와 package/config/helper 입력을 반영하며 절대 경로와 생성 시각을 기록하지 않는다. 루트 pack 도구가 현재 name/version/digest와 공개 export 대상 존재를 확인한 뒤 `npm pack --ignore-scripts --json`을 실행한다. 완성 stamp가 없거나 source가 달라진 stale dist는 소비용 tarball로 포장하지 않는다.
