# 011 배포와 생성기 준비·진행 검토

2026-10-07의 읽기 전용 준비 검토에서 실제 구현·검증 기록으로 갱신했다. **010과011은 구현·로컬 검증을 완료했다.** 현재 공통 frontend0.2.0/backend0.2.0-SNAPSHOT의 생산·pack·생성기·외부 소비와0.1.0→0.2.0→0.1.0 upgrade/rollback, compiled Docs22/Controls10까지 실제 통과했다. 기존 API·DDL은 유지한다. 자체 코드는 내부 `UNLICENSED`이며 공개 npm publish·원격 registry 운영은 범위 밖이다. WorkboardVue/workboard의 실행 자료를 사용하지 않는다.012는 준비 검토만 완료했고 구현·실행은 대기다.

각 manifest는 `private:true`, `license:'UNLICENSED'`, `files:['dist','README.md','UNLICENSED','THIRD_PARTY_NOTICES']`와 types-first compiled exports를 사용한다. source registry나 `src/*`·`dist/*` wildcard를 공개하지 않는다. 루트 workspace 개발은 source aliases를 쓰지만 외부 소비자는 완성한 tarball만 설치한다. 다섯 패키지의0.1.0 최초 생산 build는 실제 exit0이며 현재0.2.0은 stamp/digest와 pack 내용을 다시 확인했다. [생산 설계](011-공통패키지-배포설계.md), [의존성 보완 후 산출물 증거](../검증/011-library-build-after-dependencies.json)를 따른다.

UI [source-entries.json](../../frontend/packages/ui/source-entries.json)은 정확히 `{format:1,entries:{...}}`로 `.`, `./styles`, `./tokens`, `./table`, `./charts`, `./editor`, `./board`, `./image` 8키와 source 경로를 제공한다. 계약 도구는 공개22개를 추출하고 metadata format2를 배포한다. build는 모든 bare vendor/subpath를 외부화하고 자체 상대 chunk를 생성한다. AST 후처리는 상대 import/export/import-type/import-equals만 실제 선언 대상의 `.js` specifier로 정규화한다. `.vue.js`의 타입 대상은 `.vue.d.ts`이며 주석·업무 문자열은 치환하지 않는다.

UI CSS는 SFC scoped CSS까지 포함한 **단일 `@sc/ui/styles`**다. 소비 앱은 `vuetify/styles` 뒤에 가져온다. `@sc/ui/tokens`는 생성 Sass이며 `@use '@sc/ui/tokens' with ($sc-emit-css:false)`를 보존한다. native Sass에서는 `pkg:@sc/ui/tokens`와 NodePackageImporter를 사용한다. 선택 JS entry가 나뉘어도 현재 한 UI manifest의 선택 dependencies 설치 비용과 단일 CSS 포함량은 유지된다.

완성 build만 `dist/build-manifest.json`의 `{format:1,name,version,inputsDigest}`를 기록한다. pack 도구는 현재 source/config/helper digest와 name/version·export 대상 존재를 검사하고 `npm pack --ignore-scripts --json`을 실행한다. 설치 시 source build/prepare로 누락 산출물을 복구하지 않는다. source/declaration map·원본 source·Story/test·Reference DTO·DB·secret·업로드·실행 자료는 pack allowlist 밖이다.

## 실제 배포 세트·검사기 결과

현재 [0.2.0 artifact 검사](../검증/011-package-artifacts-v02.json)는 npm5/Maven7 PASS, [0.2.0 negative25](../검증/011-package-gates-v02.json)는 보호128파일 SHA 변경0이다. 공통 Maven0.2.0-SNAPSHOT과 frontend0.2.0 cohort를 사용하며 앱 자체 버전·API·DDL은 바꾸지 않는다. 아래 최초0.1.0 candidate2 기록과 손상/실패 세트는 불변 보존한다.

[최종 artifact 검사](../검증/011-package-artifacts-final.json)는 candidate2의 **5개 npm tarball + 7개 Maven 파일 PASS**다. Maven은 공통 parent/core/autoconfigure/Starter 4좌표의 4POM·3plain JAR이며 앱 executable JAR를 배포 세트에 넣지 않는다. 프런트 버전은 `0.1.0`, 당시 공통 Maven 좌표는 `0.1.0-SNAPSHOT`이고 생성 앱 자체 `1.0.0`과 분리한다. [격리 Maven 생산](../검증/011-backend-artifacts-first.json)은 공통 artifact용 빈 repository에서 출발했다.

[실제25개 negative gate](../검증/011-package-gates-final.json)는 export 누락·미선언 bare/declaration 참조·forbidden file·metadata/hash/경로 등 손상 세트를 거절했다. 보호128파일 SHA 변경0과 임시 추출 정리를 확인했다. artifact checker는 내용·AST·파일을 읽는 검사다. package 실행·SSR·consumer 브라우저 성공을 이 결과에 합산하지 않는다. 세부 계약은 [패키지 계약 검증](011-패키지계약검증.md)에 있다.

초기 실패를 보존한다. [첫 checker 실패](../검증/011-package-artifacts-first.json)는 실제 UI 내부 helper 추론 `.d.ts`의 미선언 `@tanstack/table-core`/`@tanstack/virtual-core` 문제였다. package-local 실제 `9.2.6`/`3.17.11`, 모두 MIT를 exact 직접 의존성에 추가하고 NOTICE·UI를 재생성했다. [두 번째 실패](../검증/011-package-artifacts-second.json)는 상대 `export *` graph를 named export checker가 따라가지 못한 오탐이었다. 실제 공개 export를 줄이거나 검사를 꺼서 우회하지 않고 AST graph 추적을 보완한 뒤 최종 PASS를 확인했다.

직접 runtime dependency/peer의 실제 설치 version/license와 LICENSE/COPYING/NOTICE 원문을 package-local 고지에 담았다. import-only vendor도 실행하지 않고 탐색하고 LICENSE 디렉터리만 있으면 거절한다. 이는 전체 transitive 라이선스 inventory 완료 주장이 아니다. 자체 `UNLICENSED`와 vendor MIT·ECharts Apache-2.0을 서로 바꾸지 않는다. ExcelJS 하위 uuid `11.1.1` 루트 override는 외부 앱에 자동 전파되지 않으므로 생성 root에도 명시하고 별도 실제 install/audit·XLSX를 검사한다.

[Starter 생성기](011-Starter생성기.md), [create-starter.mjs](../../scripts/create-starter.mjs), [template allowlist](../../templates/starter-v1/template.json)는 실제 구현됐다. 첫 외부 Maven은 parent repository의 `file://${project.basedir}/../vendor/maven`이 너무 일찍 해석되어 [첫 build](../검증/011-consumer-build-first.log)에 실패했다. portable `file:` URI를 CLI `-Dsc.generated.vendor=...`로 전달한 candidate2도 parent model에 raw property가 남아 [두 번째 build](../검증/011-consumer-build-second.log)에 실패했다. 두 실패를 보존하고 Maven settings active profile의 repository bootstrap으로 수정했다. 새 앱은 Boot3.5.16/JDK21/H2·자체 Notes migration/DTO/Query·명시 Feign 목록을 사용한다. Notes detail/쓰기는 JPA, typed 목록은 Querydsl, 같은 DS/TM 집계는 MyBatis다.
