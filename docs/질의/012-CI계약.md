# 012 CI 계약

상태: workflow 소스·정적 검증만 완료. GitHub 원격 실행·Linux Docker 운영 검사·신규 v2 cold consumer의 성공은 아직 표시하지 않는다. 로컬 개별 기능 결과는 해당 검증 JSON을 원본으로 삼는다.

## 세 작업의 책임

[verify workflow](../../.github/workflows/verify.yml)는 `verify`, `package-consumer`, `operations` 세 작업을 사용한다. 기존 checkout/setup-node/setup-java/upload-artifact의 `@v4`와 최소 `contents: read` 권한을 유지한다. Node 24.16.0, npm 11.13.0, JDK 21, Ubuntu 24.04가 기준이다.

| 작업             | 실행과 경계                                                                                                                                                                                      | 제한 시간 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------- |
| verify           | 재현 설치를 포함한 scripts/build.sh, Java processor 성공·실패 gate, 기본 OFF 실제 OpenAPI, 공통 타입, Storybook·Docs/Controls·a11y 음성 gate, 선택 파일 프로필, 일반 JAR UI/서버 회귀            | 45분      |
| package-consumer | 실제 5개 npm pack·4좌표/7파일 Maven·artifact/generator 음성 gate, 저장소 밖 신규 앱, 독립 npm lock/Maven 캐시, metadata→actual API→프런트→최종 서버 verify, 공개 타입과 설치 UI·파일 선택 프로필 | 45분      |
| operations       | 새 private 연결 설정·작업별 6서비스 Compose·기본 OFF build·실제 MQ·운영 JAR/복구/관측·Grafana·운영 UI·선택 Docker 앱                                                                             | 60분      |

package-consumer는 현재 framework 0.3.0 배포 세트와 templateVersion 2를 실제 artifact manifest에서 선택한다. 생성기가 0.1.0/0.2.0에 v1을 선택하는 보호 검사도 유지한다. Sourceguard와 초기 오류 근거를 삭제하지 않는다. 외부 앱의 Notes API는 actual generated 타입을 사용하고 운영 기술 API는 공개 runtime 계약을 사용한다. 기존 011 소비 검증기의 파일 이름이 `011-generated-*`로 유지되므로 이번 CI는 `ci012` label로 분리하며 해당 결과도 수집한다. 도구의 과거 단계 필드는 framework cohort나 신규 원격 성공을 의미하지 않는다.

## 운영 작업의 실제 명령 계약

새 RUNNER_TEMP 하위 canonical700 디렉터리를 만들고 GITHUB_ENV에는 경로·project·JDK 위치만 쓴다. `prepare-operations.py --home`은 bootstrap·broker·observer·Grafana 연결 파일을 모드600으로 생성한다. 값은 환경 변수 목록이나 stdout/artifact에 넣지 않는다. `.runtime`·기존 사용자 DB·업로드·secret를 사용하지 않는다.

Compose project는 `scframework-012-${GITHUB_RUN_ID}-${GITHUB_RUN_ATTEMPT}`이며 고정 외부 사용자의 project를 건드리지 않는다. `config --quiet` 후 `up -d --wait --wait-timeout 180`으로 RabbitMQ/Prometheus/collector/Tempo/Loki/Grafana 여섯 서비스와 초기화 컨테이너를 기동한다. 이때 app profile은 꺼져 있다. Linux host-gateway 설정은 Compose에서 명시하며 실제 원격 네트워크 연결 성공은 실행 후 확인한다.

예상 검사 개수는 현재 소스의 검사 계약이며 원격 PASS 수가 아니다. 기본 job의 broker skip과 선택 job의 실제 실행을 합쳐 하나의 실행 결과로 표현하지 않는다. API cron은 초0과 실제 ZoneId를 사용하며 PULSE는 분 단위 실행을 bounded wait로 기다린다. 서버가 Quartz/Rabbit 전달의 정확히 한 번 효과를 무조건 보장한다는 주장을 하지 않는다. 실제 inbox/효과의 같은 TX와 중복 receipt 결과로 판정한다.

## 증거와 정리

safe JSON/log·Grafana PNG·운영 Playwright 실패 자료·Maven test 보고서만 upload-artifact로 7일 보존한다. `.runtime`, secret 파일, rabbitmq.conf, H2 파일은 제외한다. 표준 job의 과거 001~011 증거 upload 경로도 유지하며 012를 추가한다. 외부 소비 앱의 공개 package-lock/provenance와 배포 tarball/POM/plain JAR은 별도 package artifact로 수집한다. 업무 입력·운영 비밀번호·token을 trace에 담지 않도록 현재 Playwright trace OFF 계약을 유지한다.

operations의 마지막 두 cleanup step은 `always()`다. 자신의 project만 `--profile app down --volumes --remove-orphans --timeout 45`로 정리하고, 새 private base의 canonical 경로·직접 부모·prefix·symlink 여부를 확인한 다음 해당 폴더만 삭제한다. Docker 전역 prune·다른 project/볼륨 삭제는 하지 않는다. package-consumer도 자신의 신규 앱·캐시 base만 제거한다. Linux runner에서의 실제 정리 성공은 원격 결과로 확인해야 한다.

## 정적 확인과 초기 검증 오류

첫 정적 검사에서는 로컬 Python의 PyYAML이 없어서 검증을 시작하지 못했다. 두 번째 시도에서는 Node `yaml`이 설치되어 있지 않았다. 의존성을 새로 설치하지 않고 실제 설치된 `js-yaml` 4.3.2로 최종 YAML을 파싱했다. 두 초기 결과를 [first](../검증/012-ci-static-first.json), [second](../검증/012-ci-static-second.json)에 보존한다.

[third 정적 결과](../검증/012-ci-static-third.json)와 [최종 정적 결과](../검증/012-ci-static-final.json)는 세 job, bash run52개, 내장 Python AST5개, @v4 action12개를 확인하여 PASS다. 최종 결과는 workflow SHA와 확정된 Docker portable CLI 인자·실제 help 종료0도 기록한다. GitHub expression은 bash 문법 검사에서만 안전한 placeholder로 바꾸며 원본 YAML을 수정하지 않는다. scoped Prettier도 통과했다. 이 검사는 GitHub expression의 원격 평가·실제 서버·Docker image·npm/Maven/browser 실행을 대신하지 않는다.

Docker 검증기는 CI에서 project/home를 명시하고 현재 Docker binary/context를 사용한다. 별도 Docker config가 없으면 자신의 임시700 디렉터리를 만들어 정리한다. 로컬 [portable 7그룹 결과](../검증/012-docker-operations-fourth.json)와 [부정 경계 결과](../검증/012-docker-portable-gates.json)는 별도 실행 근거이며 Ubuntu 원격 CI 성공으로 바꾸어 표시하지 않는다.
