# 013 공통 디자인 프레임워크

## 현재 범위와 상태

013의 **공통 규격 구현과 로컬 검증을 완료**했다. 독립 생성 앱의 설치·타입·빌드·자체 서버·실제 브라우저 검증도 완료했다. 목표는 Yzen에서 관찰한 색상·간격·버튼·입력·카드의 표현을 공통 `Sc` 컴포넌트 계약으로 제공하고 Reference·Starter·생성 템플릿이 같은 부품을 조립하게 만드는 것이다. Yzen 코드·에셋·브랜드·라이선스와 삼성 내부 LEGO 구현을 가져오지 않는다.

이전 [디자인 교정](디자인교정.md)의 unit155·Storybook105·시각16PNG 등의 결과는 당시 대시보드·셸 교정의 로컬 근거다. 이번 013의 검증은 아래 표에서 별도로 기록한다. 자동 통과·AI 캡처 검토·사용자 디자인 수락은 구분하며 사용자 수락은 미확인이다.

**현재 `127.0.0.1:18082` 실행 서버를 그대로 유지했다.** 기존 PID·JAR SHA·health·Serve 항목 보존은 [실제 확인](../../.runtime/common-ui/live-preserved.json)에 있다. 새 UI 프리뷰18083은 새 프런트와 기존18082 백엔드를 연결하므로 같은 계정·세션을 사용한다. 검증용 JAR는 원래 JAR를 별도로 복사하여 새 프런트 정적 파일만 재포장했고 비정적 엔트리 해시는 보존했다. 기존 JAR를 재빌드·재시작하거나 ScFramework의 기존 backend를 대상으로 Maven을 실행하지 않았다. 독립 생성 앱은 자신의 backend만 별도로 검증했다. WorkboardVue/React 원본·SQLite·실행 자료를 변경하지 않았다.

## 공통 규격

색·간격·폰트·radius·그림자·컨트롤 높이는 [tokens.ts](../../frontend/packages/ui/src/tokens.ts)가 원본이다. `tokens.scss`는 생성 결과이며 직접 수정하지 않는다. [theme.ts](../../frontend/packages/ui/src/theme.ts)는 Vuetify 설정을, `@sc/ui/styles`는 공통 CSS를 제공한다. 반복되는 색·padding·font 등의 표현은 공개 prop으로 선택하고 앱에서 공통 내부를 `:deep`으로 재정의하지 않는다. 업무 열 너비·콘텐츠 배치처럼 기능이 소유하는 scoped 스타일은 허용하며 모든 기존 `:deep`을 일괄 금지하지 않는다.

## 프레임워크를 사용하는 방법

소비 앱은 `@sc/ui`와 선택 진입점만 import한다. 업무 폴더에 같은 버튼·카드를 복제하거나 `packages/ui/src`를 직접 참조하지 않는다. 파일/import는 `ScActionButton`, template는 `<sc-action-button>`, 공통 CSS는 `.sc-*`다. props는 camelCase, template 속성은 kebab-case를 사용한다.

```vue
<template>
  <sc-section-card title="업무 현황" density="compact" surface="plain">
    <template #actions>
      <sc-select
        v-model="period"
        label="조회 기간"
        :options="periodOptions"
        presentation="toolbar"
        density="compact"
      />
      <sc-action-button size="sm" intent="primary" :busy="loading" @click="reloadSummary">
        조회
      </sc-action-button>
    </template>
    <sc-status-badge label="검토 대기" tone="warning" />
    <sc-kpi-card label="요청 건수" :value="requestCount" density="compact" />
  </sc-section-card>
</template>

<script setup lang="ts">
import { ref } from "vue";
import { ScActionButton, ScKpiCard, ScSectionCard, ScSelect, ScStatusBadge } from "@sc/ui";

const period = ref<string | null>("month");
const periodOptions = [{ label: "이번 달", value: "month" }];
const requestCount = ref("0건");
const loading = ref(false);
function reloadSummary() {
  // 실제 조회와 오류 처리는 기능별 Query·단일 runtime client로 연결한다.
}
</script>
```

이 코드는 공통 UI 조립 예제다. 실제 업무 숫자·조회·필드 오류·권한·저장·409 입력 보존은 소비 앱의 기능 폴더가 구현한다. 프레임워크의 UI 예제 숫자를 운영 집계로 저장하지 않는다.

검색 입력·file input·자체 SVG·canvas는 해당 책임에 맞으면 native 요소로 구현할 수 있다. 모든 native 요소를 래퍼로 바꾸는 것이 목표는 아니다. 여러 화면에서 반복되는 크기·간격·색·상태 표현은 공통 토큰과 공개 계약을 사용한다. 이미지 원본0~1 좌표·포인터 처리·업무 메뉴·세션·CSRF·권한·미저장 입력 계약을 디자인 때문에 변경하지 않는다.
