# Yzen 시각 목표를 위한 디자인 교정

## 현재 상태와 사용자 요청

**디자인 교정의 live QA·통합 빌드·새JAR관련30개·원격프리뷰 확인, 새pixel/전체Story 검증 완료, 사용자 디자인 수락 `accepted=false`**다. 001~012의 기능 구현·로컬 통합 검증 완료와 별도로 관리한다. 기존 unit149·서버196·기능 E2E·Storybook·pixel 회귀 근거는 [012 기록](012-운영모듈완료.md)과 [최종 집계](../검증/012-final-summary.json)에 보존한다. 이번 교정의 새 실행은 아래 별도 근거로 기록하며 기존 기능 성적이나 사용자 수락으로 대체하지 않는다.

사용자는 [Yzen Vue Sales](https://projects.spruko.com/vue/yzen/preview/dashboard/sales)의 디자인을 관찰해 비슷한 OSS와 자체 Vue 컴포넌트로 구현할 것을 요청했다. Yzen의 라이선스·제품 코드·유료 자산을 가져오라는 요청은 아니다. 기존 UI는 이 시각 목표를 충족하지 못해 교정한다. 공통 Sc UI를 재사용할 신규 프레임워크·Starter·Reference라는 목표, Spring/JDK21/H2·JPA/MyBatis·OpenFeign, Storybook, 세션·CSRF와 Redis/JWT/SSO 제외는 유지한다.

사용자에게 완료 상태를 설명할 때는 기능 구현, 새 디자인 QA, 사용자 디자인 승인을 각각 말한다. 루트가 새 PNG를 보고 QA PASS를 기록해도 사용자의 명시적 답변이 없으면 `accepted=false`를 유지한다. 코드를 작성했거나 기존 pixel 기준이 통과한 사실만으로 시각 목표가 충족됐다고 기록하지 않는다.

### 초기 실패와 교정 이력
