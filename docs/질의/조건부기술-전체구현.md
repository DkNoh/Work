# 조건부 기술 전체 구현 범위

사용자의 비동기 답변 **“조건부 기술까지 모두 구현”**으로 개발 범위를 확정했다. **Redis·JWT·SSO 제외는 유지**한다. 기존 표의 필수/권장/조건부는 최초 도입 판단 기준이며, 아래 조건부 기술은 모두 신규 프레임워크의 실제 구현 대상이다. 소비 프로젝트는 모듈 활성화를 선택할 수 있다.

001의 검증 기록을 유지하며 002부터 순서대로 진행한다. 라이브러리 설치·빈 adapter·설정 파일·가짜 자료 화면만으로 완료 표시하지 않는다. 공개 모듈·Reference 기능·Starter 소비·실패 경로 테스트·사용 문서·버전/라이선스 기록을 함께 제공한다.

005의 조건부 중립 모듈은 모두 구현·로컬 통합 검증을 완료했다. 실제 성적은 [005 기록](005-공통입력과화면패턴.md)의 84 unit/17 files·81 Story·20 공개 UI Docs/8 Controls·15 서버 검사·두 새 JAR E2E 18개다. Starter `src/config.ts`의 `VITE_SC_PATTERNS_ENABLED=false`로 메뉴/route 제외·optional chunk 요청 0을 확인했다. JS/CSS 산출물 2개는 남으므로 완전한 번들 제거/외부 pack 검증과 구분한다. 006 로컬 회귀 기반도 완료했다. [007 파일럿](007-요구사항파일럿.md)은 날짜·범용 감사·일반 요구사항을 구현하여 서버52·unit108·Story83·JAR E2E41·axe52회를 통과했고 모바일 목록 시각 개선 후 새 JAR·6장 이미지 검토까지 로컬 완료했다. 008 조회·매핑·외부 HTTP도 구현·로컬 통합 검증을 완료했다. 009의 실제 MyBatis 보고·서버 표/현재 페이지 가상화도 서버87·46 E2E·61 axe·12 PNG/시각 회귀를 통과하여 로컬 완료했다. 010은 구현·로컬 통합 검증을 완료했고 011은 compiled/pack/외부 소비·생성기/upgrade/rollback의 로컬 검증을 완료했고 012·원격 CI·실제 Compose 실행은 대기다.

## 구현 경계

JPA/Querydsl은 Entity 기반 동적 조건·쓰기, MyBatis는 복잡 join·집계/report를 맡는다. 동일 조회를 상시 이중 구현하지 않는다. Querydsl 유지 fork와 외부 HTTP용 OpenFeign client는 역할이 다르다. 현재 Querydsl master의 최신 Spring/Boot 조합을 Boot3.5.16 호환으로 단정하지 않는다. 008은 fork6.12/Jakarta JPA3.1·Hibernate6.6.53·H2 2.3.232·JDK21을 실제 compile·runtime 검사로 고정했다. MapStruct/Lombok 병용 processor를 검증하고 JPA Entity에 무조건 @Data를 적용하지 않는다.

Vue Query는 서버 자료, Table은 열/정렬/선택, Virtual은 렌더 범위다. Vue SFC template와 slot으로 구현하며 라이브러리 예제의 h()/JSX를 화면에 반입하지 않는다. I18n은 locale/메시지, Day.js는 날짜 처리이며 Vuetify locale도 같은 선택에 연결한다.

Grafana는 시각화, Prometheus는 지표, Tempo는 trace, Loki는 로그다. 브라우저 오류 수집·fingerprint·이력 화면은 자체 adapter로 구현한다. Quartz는 예약 실행, RabbitMQ는 비동기 전달을 맡으며 중복 방지 결과를 검증한다. Quartz schema는 Flyway가 관리하고 재기동 시 drop하는 자동 초기화를 사용하지 않는다.

모든 업무 앱의 기본 DB는 H2다. 관측 제품의 내부 metadata 저장소는 업무 DB와 구분한다. 운영 스택에도 Redis cache/ring·JWT 인증·SSO plugin을 넣지 않는다. 로컬 브로커/관측 서버의 실제 실행이 미검증이면 012를 완료 표시하지 않는다.
